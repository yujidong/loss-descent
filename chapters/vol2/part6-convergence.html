29  收敛：decoder-only、MoE 与开源运动

卷二收官。2019 年的时候，做 NLP 要在 GPT 与 BERT 之间站队、在十种注意力和四种训练目标里挑花活；到 2023 年，新发布的基座模型几乎清一色长成同一个样子：decoder-only Transformer、下一词预测、几十层、几千亿参数。架构的多样性塌缩成了共识模板。本章盘点这场收敛的三股推力（decoder-only 的经济学、稀疏化对”参数与算力解耦”的回答、开源运动对”谁能拥有模型”的回答），做一次 MoE 的最小实验，然后合上卷二。

Tip算力需求

A 级：笔记本 CPU · MoE 对照实验约 2 分钟。

  • 算力：万卡集群成为旗舰训练的门槛；MoE（千级专家）成为”参数上量、算力不炸”的主路（GShard/Switch/后来的 Mixtral）；
  • 数据：Chinchilla 配方生效后，数据工程（清洗、去重、配比）成为模型竞争力的大头；
  • 认知：“基础模型”（foundation model）一词（2021）被广泛接受。范式收敛伴随 vocabulary 的收敛；
  • 关键事实：2023 年 2 月 LLaMA (Touvron et al. 2023) 权重泄露、7 月 Meta 干脆正式开源。开源社区的微调生态（Alpaca 一族）在几个月内把”小模型 + 好数据”的路线跑通。闭源壁垒被证明比想象中薄。

29.1 本章问题

  1. 收敛到 decoder-only 的三条理由，各自站不站得住？（5.4 伏笔的正式结算）
  2. MoE 如何解耦”参数量”与”每 token 算力”？代价是什么？（最小实验 + 诚实结果）
  3. 这场收敛排除了什么。被收敛掉的多样性，损失在哪里？

29.2 历史中的尝试（包括弯路）

decoder-only 的三张牌：①信号密度。每个 token 都产生监督（5.4 的验货结论）；②scaling 友好。目标单一、损失稳定、幂律好测（6.1 的曲线全部画在这条目标上）；③工程极简。训练即推理的彩排、KV 缓存直接可用、流水线好切。 encoder-decoder（T5 一系）与 MLM 路线没有输在”双向无用”，输在规模化时代的适配性。

MoE 的谱系：思想源头是 1991 年的混合专家（Jacobs et al.。古老的联想，与 LSTM 同年出生）；2017 年后与 Transformer 结合成稀疏层（Shazeer 的 Sparsely-Gated MoE、Google 的 Switch (Fedus et al. 2022) Transformer 每层几千专家、2023 年 Mistral 的 Mixtral 8×7B 开源爆款）。“参数存知识、算力做计算”的解耦让千亿级参数以百亿级的单 token 成本运行。

弯路：MoE 的训练之难。负载不均（几个专家被挤爆、其余闲置）、训练不稳、微调娇气。解药是一整套工程（辅助负载损失、容量因子、z-loss）。稀疏性的收益从来不是免费的。本章实验会亲手撞上这一点。

开源运动：LLaMA（2023）按 Chinchilla 配方证明”小而充分训练”可行 → 泄露与正式开源 → 社区微调生态爆发 → 各家跟进（Mistral、Qwen、DeepSeek 一族）。研究-工程-社区的三级火箭取代了”单实验室闭门造模型”的旧范式。9.1 会把这段放到 Bitter Lesson (Sutton 2019) 的延长线上复盘。

29.3 核心思想

收敛的三股力，用账本语言各记一笔：

  • Decoder-only：在”信号密度 × scaling 可测性 × 工程简洁”的三维评分上全面领先。不是最优的架构，是最可规模化的架构（Bitter Lesson 的架构版判决）；
  • MoE：把”参数”与”每 token 计算”解耦。知识可以更便宜地存，取用时只付路过的那部分算力。代价是训练复杂度与负载均衡的新税；
  • 开源：把”基座”从产品降级为商品。当架构收敛、配方公开（Chinchilla）、数据管道可复制时，护城河只剩数据、算力与对齐（后两者正是卷三的主题）。

收敛的代价：被收敛掉的还有多样性。encoder 路线在检索/嵌入场景仍是活的传统（5.4 的回声），稀疏注意力、线性复杂度、状态空间模型（4.2 的 RNN 还魂一族）都在等待”长上下文的账单”到期后接管（8.x）。收敛是特定账本下的最优解，账本变了，格局重开。

29.4 从零实现

MoE 对照实验：dense d=32（第二块 MLP 隐层 4d=128）vs 同模型第二块换成 MoEMLP（2 位专家、各 2d=64 隐层）。总参数相近、每 token 活跃算力减半：

import numpy as np

from dlbook.data.corpus import char_corpus, make_grammar_corpus
from dlbook.transformer import MiniGPT
from dlbook.transformer.layers import MoEMLP
from dlbook.utils import set_seed

set_seed(42)

arr_t = np.array(char_corpus(make_grammar_corpus(60000, seed=0))[0])
arr_v = np.array(char_corpus(make_grammar_corpus(12000, seed=1))[0])
V = len(char_corpus(make_grammar_corpus(60000, seed=0))[1])  # 词表取自完整训练文本
vb = np.stack([arr_v[s : s + 65] for s in np.random.default_rng(7).integers(0, len(arr_v) - 65, size=200)])


def train(model, steps=1500, seed=0):
    rng = np.random.default_rng(seed)
    for step in range(steps):
        lr = 0.15 * min(1.0, (step + 1) / 150) * (1 - 0.9 * step / steps)
        starts = rng.integers(0, len(arr_t) - 65, size=16)
        batch = np.stack([arr_t[s : s + 65] for s in starts])
        model.loss_and_backward(batch)
        model.step(lr, clip=1.0)
    return model


dense = MiniGPT(V, d_model=32, n_heads=2, n_blocks=2, block_size=64, seed=0)
train(dense)

moe = MiniGPT(V, d_model=32, n_heads=2, n_blocks=2, block_size=64, seed=0)
moe.blocks[1].mlp = MoEMLP(32, n_experts=2, seed=77)
train(moe)

print(f"dense: val loss = {dense.loss_on(vb):.3f}")
print(f"MoE:   val loss = {moe.loss_on(vb):.3f}")
print(f"专家使用率: {np.round(moe.blocks[1].mlp.usage, 3)}")
dense: val loss = 1.909
MoE:   val loss = 1.938
专家使用率: [0.741 0.259]

典型的诚实结果：MoE 1.94 对 dense 1.91。打平或略输，且使用率失衡（约 0.74/0.26，没有负载均衡辅助损失的约束）。这不是 MoE 的失败，是尺度与配方的证词：

  1. 收益需要尺度：两位专家在 2.7 万参数里分不到足够的专业化空间；真实 MoE 的收益在百亿千亿参数、多领域数据时才兑现（专家按领域/句法分工）；
  2. 负载均衡是生命线：使用率失衡意味着相当一部分参数在偷懒。Switch Transformer 们靠辅助损失与容量因子驯服它（我们的玩具没装，练习 3 补上）；
  3. 训练税：稀疏路由的梯度不如 dense 稠密。同预算下略慢是常态。

玩具的零结果与产业的千亿结果并存，正是”账本第二问（数据）与第三问（规模）决定技术适用域”的又一课。把这句话和 2.3（dropout 在玩具上平庸、在大模型上辉煌）对照：同一门课，卷一讲过一遍了。

29.9 练习

  1. 造轮子：给 MoEMLP 加负载均衡辅助损失（\(L_{aux} = E \sum_e f_e \cdot p_e\)，\(f_e\) 为使用率、\(p_e\) 为平均门概率），权重 0.01，重训。使用率与 loss 各怎么变？
  2. 预测再运行：把 MoE 的路由从 top-1 改成 top-2（两位专家输出平均）。loss、使用率、每 token 算力各怎么变？（稠密化是 MoE 稳定性的常见退路。）
  3. 消融：换一个 seed 重跑 MoE 对照五次，统计胜负。1.94 vs 1.91 在方差之内吗？（样本量意识：一切”打平”结论都要过这关。）
  4. 论文映射：用四问账本拆 LLaMA。注意它”买到”一栏几乎全是可复制性与开放性，闭源论文里这些格子是空的。
  5. 进阶（卷三预习）：用卷二的任意 base 模型（我们的 MiniGPT）采样 200 个字符，统计其中”完整英文单词”的比率与”重复片段”的比率。为 7.1 的”续写怪癖”观察提前采证。
Note练习答案

练习 1：使用率趋向均衡（如 0.55/0.45），loss 或微升或微降。均衡与质量是两本账，辅助损失买的是前者的保险；真实系统里没有它，MoE 会退化成”单专家 + 死权重”。

练习 2：top-2 更稳（梯度更密）但每 token 算力翻倍。稀疏性的收益被稀释；实践中 top-1（Switch）与 top-2（Mixtral）各有阵地，是”稳定性 vs 稀疏度”的汇率问题。

练习 5 提示：典型样本里”完整词”过半但”重复片段”显著（循环复读是循环网络时代的老病，在弱 base 模型上仍可见）。7.1 会把这类观察系统化为”分布的怪癖”，并论证为什么需要后训练。

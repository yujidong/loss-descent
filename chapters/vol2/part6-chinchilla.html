27  Chinchilla (Hoffmann et al. 2022)：等算力下的再平衡

上一章的曲线回答了”更大更好吗”，却没有回答一个更贵的问题：给我一笔固定的算力，该怎么花？ 2020 年的实践答案是”买参数”。Kaplan 的曲线读起来像”大模型优先”。2022 年，DeepMind 的 Hoffmann 等人（论文代号 Chinchilla）用四百多次受控实验重算了这本账，结论掀了桌子：同等算力下，参数与训练数据应当大致等比例增长（约每参数 20 个 token）。按此配方，700 亿参数的 Chinchilla 打败了它四倍大的 Gopher。行业随即转向”更小的模型、更多的数据”。LLaMA (Touvron et al. 2023) 一族由此而生。本章在玩具上重演这本账的算法：等算力扫描。

Tip算力需求

B 级：笔记本 CPU 约 5–6 分钟（四档等算力训练；各档独立可跑）。

  • 算力：训练预算进入亿美元时代；“训练一次的沉没成本”让配比错误的代价变得惊人；
  • 数据：高质量文本的获取开始成为瓶颈的先兆（9.2 的数据墙前夜）；
  • 认知：GPT-3 之后行业默认”参数量 = 排行榜名次”；Chinchilla 之前已有零星质疑（例如”训练不足的大模型”现象），但缺少系统性的再核算；
  • 关键事实：Chinchilla 的四百多个实验点本身比结论更宝贵。它把”如何做 scaling 实验”（统一配方、等算力族、三维扫描）变成了方法论模板，此后所有大厂的技术报告都在模仿这个文体。

27.1 本章问题

  1. 等算力约束是什么意思，如何在实验里实现？（参数 × 步数 ≈ 常数）
  2. 等算力下扫尺寸，曲线是什么形状？（预期一个 U 型。最优尺寸夹在”小而充分训练”与”大而欠训练”之间）
  3. 最优点告诉了我们什么？为什么它随算力预算移动？

27.2 历史中的尝试（包括弯路）

Kaplan 的读法与偏差：2020 (Kaplan et al. 2020) 年的定律说”大模型在相同算力下更优”。但那些测量里的模型大多没有训到收敛，且固定了一批训练细节（学习率日程的长度、临界批次）。在欠训练的世界里比较大模型，会系统性高估”大”的边际收益。Chinchilla 的第一刀就砍在这里：统一配方、训到位、再比较。

三族方法，一个结论：Hoffmann 等人用三种独立方法（固定模型扫数据、固定数据扫模型、等算力参数化拟合）交叉验证，收敛到同一个配比（每参数约 20 token）。多方法的一致性比单一方法的精度更有说服力。研究方法论的一堂公开课。

回响：Gopher（2800 亿参数）被 Chinchilla（700 亿）以相同算力击败；Meta 的 LLaMA（2023）按新配方用”小”模型追平大模型，并把权重开源。配比的修正直接催生了开源时代的可行路线（6.4 的剧情）。此外它还改写了推理经济学：训练一次省下的钱之外，小模型的每一次推理都更便宜。部署时代的隐藏红利。

弯路：把 20 token/参数当物理常数。后续研究（如对多轮训练、数据复用的再核算）表明这个比率依赖设定；把它当铁律的做法很快被打破。研究结论的适用域与结论本身同样重要。账本栏目的老教导。

27.3 核心思想

等算力族（iso-compute family）：固定 \(C \approx N \times S\)（参数 × 步数），扫描 \(N\)。每个预算 \(C\) 下存在一个计算最优尺寸 \(N^*(C)\)：比它小，模型容量不足（训练步数浪费在已收敛的模型上）；比它大，步数不够（模型欠训练，参数浪费）。把所有预算的最优点连起来，得到 \(N^*(C)\) 的 scaling。这就是 Chinchilla 配比。

直觉版：训练像烧砖。参数是窑的容积、数据是柴火。窑太大柴不够，烧出半熟的砖；窑太小柴太多，烧完还剩火。约束不是窑也不是柴，是总热量。

为什么它推翻了 Kaplan：两者并不真的矛盾。差别在”训练到什么程度算数”。Kaplan 族的比较隐含”欠训练也算”，Chinchilla 族要求”算力花完即止”。同样的数据、不同的实验协议、不同的结论。读到任何 scaling 主张时，先问它的协议。

对本书主线的意义：这是 loss 账本最辉煌的一页。“如何最便宜地降 loss”的会计学。研究从”找到更好的方法”扩展到”找到更优的资源配置”，这门手艺此后统治了工业界的模型训练。

27.4 从零实现

复用上一章的全部装备，只把扫描协议换成等算力：

import time

import numpy as np

from dlbook.data.corpus import char_corpus, make_grammar_corpus
from dlbook.transformer import MiniGPT
from dlbook.utils import set_seed

set_seed(42)

arr_t = np.array(char_corpus(make_grammar_corpus(60000, seed=0))[0])
arr_v = np.array(char_corpus(make_grammar_corpus(12000, seed=1))[0])
V = len(char_corpus(make_grammar_corpus(60000, seed=0))[1])  # 词表取自完整训练文本
vb = np.stack([arr_v[s : s + 65] for s in np.random.default_rng(7).integers(0, len(arr_v) - 65, size=200)])


def train_eval(d_model, steps, seed=0):
    heads = 2 if d_model <= 32 else 4
    m = MiniGPT(V, d_model=d_model, n_heads=heads, n_blocks=2, block_size=64, seed=seed)
    rng = np.random.default_rng(seed)
    for step in range(steps):
        lr = 0.15 * min(1.0, (step + 1) / 150) * (1 - 0.9 * step / max(steps, 1))
        starts = rng.integers(0, len(arr_t) - 65, size=16)
        batch = np.stack([arr_t[s : s + 65] for s in starts])
        m.loss_and_backward(batch)
        m.step(lr, clip=1.0)
    return m, float(m.loss_on(vb))


BUDGET = 27293 * 1200  # param-steps（以 d=32 的上一章配置定锚）
configs = [(8, 2237), (16, 7517), (32, 27293), (64, 103709)]

results = {}
for d, n in configs:
    steps = int(BUDGET / n)
    t0 = time.time()
    m, vl = train_eval(d, steps)
    results[d] = vl
    print(f"d={d:3d} ({n:6d} 参数, {steps:5d} 步): val = {vl:.4f} ({time.time()-t0:.0f}s)")
d=  8 (  2237 参数, 14640 步): val = 1.7329 (205s)
d= 16 (  7517 参数,  4357 步): val = 1.5540 (65s)
d= 32 ( 27293 参数,  1200 步): val = 1.8942 (41s)
d= 64 (103709 参数,   315 步): val = 2.1518 (22s)
import matplotlib.pyplot as plt

ds = list(results)
plt.figure(figsize=(5.5, 4))
plt.plot(ds, [results[d] for d in ds], "o-")
plt.xscale("log", base=2)
plt.xlabel("model size (d_model, log)")
plt.ylabel("val loss at fixed compute")
plt.title("The iso-compute U-curve: too small underfits, too big undertrains")
best = min(results, key=results.get)
plt.axvline(best, ls="--", c="red", label=f"compute-optimal: d={best}")
plt.legend()
plt.show()

典型读数（对照你的预测）：d=8 → 1.73，d=16 → 1.55（谷底），d=32 → 1.89，d=64 → 2.15。清晰的 U 型。三个教训当场兑现：

  • 上一章的冠军（d=64）在本协议下垫底：315 步远不够喂饱十万个参数。“更大更好”是”步数富余”世界里的结论；
  • 谷底在 d=16：等算力下，中等身材 + 充分训练胜过巨人 + 浅尝辄止；
  • 有趣的细节：d=8（步数超多）拿到 1.73，好于 d=32/64。小模型充分训练的顽强，正是 LLaMA 路线的玩具版。

玩具与现实的换算：真实 Chinchilla 配比约 20 token/参数。我们的谷底 d=16：训练 4357 步 × 每步 1024 token ≈ 4.5M token 对 7.5K 参数。比率约 600，远大于 20。原因正是上一章的那堵墙：六万字符的语料让大模型无利可图，把最优点狠狠推向小模型。最优配比是（算力、数据供给）的函数。数据稀缺的世界里，“小而精”永远正确；数据充沛的世界里，配比才由算力单方面决定。我们的玩具恰好站在”数据稀缺世界”，与 2024 年后的人类殊途同归（9.2 的伏笔，以想不到的方式提前）。

27.5 消融实验

预算加倍，谷底去哪？ 把 BUDGET ×2，重扫（每档步数加倍）。观察谷底是否右移、以及右移多少：

BUDGET2 = BUDGET * 2
results2 = {}
for d, n in configs:
    steps = int(BUDGET2 / n)
    m, vl = train_eval(d, steps)
    results2[d] = vl
    print(f"预算x2 d={d:3d} ({steps:5d} 步): val = {vl:.4f}")
预算x2 d=  8 (29281 步): val = 4.2507
预算x2 d= 16 ( 8714 步): val = 0.9220
预算x2 d= 32 ( 2400 步): val = 1.6907
预算x2 d= 64 (  631 步): val = 2.3347

典型结果：谷底向右移动一档（更多算力买得起更大的”充分训练”模型），但是，受数据墙牵引，移动幅度有限。\(N^*(C)\) 的轨迹 = 算力推着走、数据墙拦着走。两股力的合力方向，就是 6.4 与 9.2 要继续展开的产业剧情。

27.9 练习

  1. 造轮子：实现三维网格的迷你版（3 尺寸 × 3 步数，等量九点），画出等 loss 等高线图。\(N^*(C)\) 从等高线的切点上读出来。
  2. 预测再运行：把语料换成 12 万字符（数据墙外推），谷底往哪移？先按”两股力”的框架预测，再验证。
  3. 消融：等算力扫描里把学习率日程的 warmup 拿掉（小步数档几乎没有 warmup 余地），谷底移动吗？。短训练的配方与长训练不同，这正是 Chinchilla 方法论中最容易被忽视的细节。
  4. 论文映射：用四问账本（+算力账本）拆 Chinchilla。注意它”买到”的是决策规则而非能力，这类论文的价值如何在学术评价体系里被低估又如何被工业界兑现？
  5. 进阶：给我们的玩具算”token/参数”配比曲线（对每个预算档算 \(C/N^*\)），观察它随预算的变化方向，与真实世界 20 token/参数 的来源（数据充足假设）对照。
Note练习答案

练习 2：谷底右移（数据墙退远，算力独大）。移动幅度取决于新增数据的质量；若只是把旧语料复制一遍，墙不动（信息量未增）。

练习 3：小步数档受 warmup 影响最大（预算的相当比例花在暖机上）。拿掉 warmup 后短训练反而更高效，谷底左移。配比结论对配方细节敏感，所以，论文复现比想象中难。

练习 5 提示：玩具的配比随预算上升（数据墙约束松了）；真实世界在数据充足段的渐近值约 20。把两条线画在同一张图上，“研究结论的适用域”就有了几何形状。

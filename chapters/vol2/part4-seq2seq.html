21  seq2seq：翻译即条件语言建模

2014 年，Sutskever、Vinyals 与 Le (Sutskever et al. 2014) 发表了一个影响深远的工程直觉：读句子的 RNN 最后的隐藏状态，就是这句话的”意思”。把这一个向量交给另一台 RNN，让它生成另一种语言的句子，翻译就完成了。编码器-解码器（encoder-decoder）从此成为一切”输入序列→输出序列”任务的标准骨架：翻译、对话、摘要、语音识别，直到今天大模型的 prompt → 回答本质上仍是它的变体。本章我们搭出这个骨架，训练它做”序列反转”的玩具翻译，然后亲手撞上它的著名软肋：固定维度的向量装不下任意长的句子。这个软肋催生了注意力（下一部分的主角）。

Tip算力需求

A 级：笔记本 CPU · 主实验约 1 分钟。

  • 算力：单 GPU 训数日；2016 年 9 月，谷歌翻译全线切换 GNMT（8 层 LSTM 的 seq2seq）。端到端神经翻译在一夜之间替换了短语统计系统，用户当周就注意到译文突然变流畅；
  • 数据：欧盟议会的平行语料（数百万句对）是主要燃料。“数据从哪来”的答案第一次是”政府公文”；
  • 认知：此前机器翻译的主流是短语表 + 对齐模型的统计派（IBM 模型的后代）；深度学习被视为”特征学习”，直接生成整句仍属激进；
  • 关键事实：Sutskever 论文的关键 trick 之一是把输入句子倒序喂给编码器。因为梯度衰减，编码器末端的词（离解码器最近）恰好是最需要的；用数据的花招补偿结构的缺陷，这个细节预告了下一章的全部剧情。

21.1 本章问题

  1. 编码器-解码器骨架在受控任务上如何工作？（序列反转：输入 3–5 个数字，输出其倒序。需要”整句读完再逆着写”，强迫信息穿过整个编码过程）；
  2. 它的软肋如何量化？（长度外推：训练时只见过长度 ≤5，测试更长时性能崩塌。固定向量的容量账单）。

21.2 历史中的尝试（包括弯路）

弯路一：短语统计翻译的对齐噩梦。统计派的短语表要维护”哪段对哪段”的离散对应，长句的组合管理复杂而脆弱。seq2seq 用一个连续向量替代整张对齐表。放弃可解释性，换取端到端的可训练性。1.2 的母题再次上场：离散知识工程 vs 连续可学习表示。

弯路二：COD 的滑窗生成。早期神经翻译试图滑动窗口逐段翻译再拼接。上下文被窗口切断。seq2seq 的贡献正是把整句的全局决策交给编码器终态。

输入倒序的启示：作者们发现把源句倒过来喂，BLEU 显著上升。因为解码器先要输出的词，在倒序输入里恰好离编码器终态最近（梯度衰减的补偿）。这个 trick 在 2017 年被注意力彻底作废。结构缺陷的补丁永远不如修结构本身。

teacher forcing：训练时解码器每一步都喂真实的上一个词而非自己的预测。并行高效，但训练与推理（吃自己的预测）之间存在暴露偏差。这个偏差在今天的 LLM 时代仍有回响（7.2 的训练-解码不一致讨论）。

缓一缓。这一节的四个条目连成一条线：短语统计的对齐表笨重，滑窗生成切断上下文，seq2seq 用一个连续向量取代两者；输入倒序与 teacher forcing 是两件工程补丁——前者治梯度可达性，后者换来训练效率、埋下暴露偏差。骨架与补丁的分工，在后面的章节里反复出现。

先做两个思想实验（写下来再运行）：

  1. 容量账：把长度为 5、词表 12 的序列（\(12^5 \approx 25\) 万种）全压进一个 64 维向量。信息论上绰绰有余。但长度为 10 呢（\(12^{10} \approx 6\times10^{10}\)）？64 维浮点向量的”有效容量”够吗？训练要学到这个映射的难度呢？
  2. 预测崩塌曲线：模型在长度 3–5 上训练到接近满分。画出你预测的”精确匹配率 vs 测试长度（3–8）“曲线。崩塌是断崖还是缓坡？从哪一级开始？

第 2 问的答案将直接成为本章的主图。写完再往下。

21.3 核心思想

编码-解码 = 两段式条件语言建模：

\[P(y_1..y_T \mid x_1..x_S) = \prod_t P(y_t \mid y_{<t},\ \mathbf{c}), \qquad \mathbf{c} = h_S^{enc}\]

编码器 LSTM 把源句读成终态 \(\mathbf{c}\)（本章语境下就是细胞状态与隐藏状态），解码器以 \(\mathbf{c}\) 为初态做 4.2 的自回归生成。翻译被拆成”压缩”与”条件展开”两半。后半是语言建模（4.1/4.2 的全部装备），前半是本章的新事物。

瓶颈定理（非正式）：解码的每一步都只通过 \(\mathbf{c}\) 看见源句。若源句含 \(I\) 比特信息而 \(\mathbf{c}\) 的有效容量不足（或编码器没学好压缩），解码器无法事后补救。损失在压缩一步就永久发生了。长度外推实验就是这个定理的实验版本。

与 3.3 的范式同构：预训练-微调（3.3）是”通用特征 + 专用头”；编码-解码是”通用压缩 + 专用生成”。两者共享同一个深层结构：把难题拆成一个重的表示学习 + 一个轻的任务适配。这个模式将统治到 GPT 时代（预训练 + 下游微调/对齐，7.2）。

缓一缓。本节立了一个非正式的”瓶颈定理”：解码的每一步都只通过向量 \(\mathbf{c}\) 看见源句，若压缩一步没保住信息，解码器无法事后补救——长度外推实验就是它的实验版本。而”重表示学习 + 轻任务适配”的拆分，与 3.3 的预训练-微调同构。

21.4 从零实现

dlbook.rnn.Seq2Seq：编码/解码各一台 LSTM，解码器初态 = 编码器终态（梯度沿 backward 的初始状态接口回传到编码器）。任务：数字序列反转（词表 0=BOS、1=EOS，2–11 为数字）。

import numpy as np

from dlbook.data.corpus import make_reversal_task
from dlbook.rnn import Seq2Seq
from dlbook.utils import plot_loss_curves, set_seed

set_seed(42)

inputs, targets = make_reversal_task(n=400, max_len=5, seed=0)   # 训练: 长度 3–5
val_in, val_tg = make_reversal_task(n=200, max_len=5, seed=1)

model = Seq2Seq(12, hidden=64, seed=0)
losses = []
for epoch in range(25):
    total = 0.0
    order = np.random.default_rng(epoch).permutation(len(inputs))
    for i in order:
        total += model.loss_and_backward(inputs[i], targets[i])
        model.step(0.05)
    losses.append(total / len(inputs))
plot_loss_curves({"reversal loss": losses}, title="seq2seq learns to reverse");
def exact_acc(model, pairs):
    ok = sum(model.greedy_decode(i) == t for i, t in pairs)
    return ok / len(pairs)

print(f"验证集（长度 3–5）精确匹配: {exact_acc(model, list(zip(val_in, val_tg))):.3f}")
print("示例:", model.greedy_decode(val_in[0]), "目标:", val_tg[0])
验证集（长度 3–5）精确匹配: 0.965
示例: [0, 2, 11, 9, 7, 1] 目标: [0, 2, 11, 9, 7, 1]

25 个 epoch、几秒钟：loss 2.18 → 0.001，整句精确匹配约 97%。编码器学会了把”哪几个数字、什么顺序”压进 64 维，解码器再逆序释放。玩具尺度上，“向量即意思”近乎魔法。

主实验：长度外推（固定向量的账单）。 在训练分布（长度 ≤5）之外逐级测试：

import matplotlib.pyplot as plt

def pairs_of_length(L, n=600, seed=9):
    ins, tgs = make_reversal_task(n=n, max_len=L, seed=seed)
    return [(i, t) for i, t in zip(ins, tgs) if len(i) == L + 2]

accs = []
lengths = (3, 4, 5, 6, 7, 8)
for L in lengths:
    pairs = pairs_of_length(L)
    acc = exact_acc(model, pairs)
    accs.append(acc)
    print(f"长度 {L}（{len(pairs)} 条）: 精确匹配 {acc:.3f}")

plt.figure(figsize=(5.5, 3.8))
plt.plot(lengths, accs, "o-")
plt.axvline(5.5, ls="--", c="gray", label="max length seen in training")
plt.xlabel("sequence length")
plt.ylabel("exact match")
plt.title("The fixed-vector bill comes due")
plt.legend()
plt.show()

典型读数：长度 3–5 在 0.92 以上；长度 6 掉到 0.51；长度 7 剩 0.25、长度 8 接近 0。训练边界之外，性能断崖。对照你在「停一停」画的预测曲线：崩塌形态对了吗？注意：崩塌的编码器从未学过长句的压缩方式。它背过的是”如何压 5 个”，不是”如何压任意个”。分布外，能力来自分布内。这句话将在 6.3（涌现的边界）与 9.2（评测外推）反复回响。

缓一缓。把读数对齐：边界内（长度 3–5）精确匹配 0.92 以上，长度 6 掉到 0.51，长度 8 接近 0——训练边界之外是断崖，不是缓坡。断崖的原因不在向量容量不够，在编码器从未学过长句的压缩方式：它背过的是”如何压 5 个”，不是”如何压任意个”。

21.5 消融实验

倒序输入 trick 复刻。 Sutskever 的补丁：把编码器输入倒过来喂（inputs[i][::-1]）。在翻译里，这使”最先要输出的词”离编码器终态最近。那么对反转任务，这个补丁该起什么作用？先想清楚再运行（提示：反转任务最先要输出的数字，本来就在输入的末尾）。复刻并与正序对照，看两者在长度外推上的差异：

model_rev = Seq2Seq(12, hidden=64, seed=0)
for epoch in range(25):
    order = np.random.default_rng(epoch).permutation(len(inputs))
    for i in order:
        model_rev.loss_and_backward(inputs[i][::-1], targets[i])  # 源句倒序
        model_rev.step(0.05)

print("倒序输入版的外推曲线:")
for L in (5, 6, 7, 8):
    # 编码同样要倒序喂
    pairs = [(i[::-1], t) for i, t in pairs_of_length(L)]
    print(f"  长度 {L}: {exact_acc(model_rev, pairs):.3f}")
倒序输入版的外推曲线:
  长度 5: 0.888
  长度 6: 0.414
  长度 7: 0.037
  长度 8: 0.000

典型结果：倒序版在边界内相当（长度 5：0.89 对 0.92），外推全面更差（长度 7：0.04 对 0.25）。原因正是提示里的那一点：反转任务要先输出的数字本来就离终态最近，倒序反而把它推到最远。补丁的方向依赖任务的前提；同样的补丁在翻译里有效，在这个玩具里为负。真正的解药需要解码器在每一步都能回头看任意源词。这个”回头看”的正式名字，就是下一部分的主角。

缓一缓。消融的教训：同一个补丁在两个任务里方向相反，因为”最需要的词离终态最近”这个前提只在翻译里成立。补丁依赖前提，结构不依赖——这正是把”回头看”升级为机制的动机。

21.6 本章 Loss 账本

问题 回答
在优化什么 loss？ 解码器输出词的 softmax 交叉熵（teacher forcing 下逐步平均）。语言建模的 loss 穿上了”条件”的外衣
数据从哪来？ 合成任务；历史上是平行语料（欧盟议会、联合国）。句对齐数据是翻译的石油
买到了什么能力？ 端到端的序列到序列映射；可微的”压缩”概念；一切生成任务的通用骨架
没买到什么？ 长度外推（断崖）；对齐的显式建模（哪个译词对应哪个源词？黑箱）；暴露偏差（训练喂真词、推理吃己词）
  • 编码器-解码器 → Transformer 的标准两段式（5.2：encoder-decoder Transformer）、今天的 chat 模型本质仍是”prompt 编码 + 回复解码”的变体（虽然统一成了单个自回归栈）；
  • 固定向量瓶颈 → KV 缓存与上下文窗口的容量经济学（9.2）。“历史装在哪、装多少”从本章起成为永恒话题；
  • teacher forcing / 暴露偏差 → RLHF 阶段”训练在人类偏好分布上、推理在自身分布上”的同构问题（7.3）；
  • “能力来自分布内” → 6.3 涌现之谜与 9.2 评测外推的原理性约束。

Sutskever, I., Vinyals, O. & Le, Q. (2014). Sequence to sequence learning with neural networks. NeurIPS.

  • 读什么：第 2 节（模型，半页）与第 3 节的输入倒序 trick 及其解释。全文最深刻的两段话藏在 trick 的动机里（梯度与源句词的”可达性”）；
  • 跳过：BLEU 细节；
  • 历史注：配套读 Cho et al. (2014) (Cho et al. 2014)（同期编码-解码 + GRU，从机器翻译的需求出发）。两篇同期同构，是”想法的空气中到期”的典型案例；以及 Bahdanau et al. (2015) (Bahdanau et al. 2015)。它是对本章瓶颈的直接回应，也就是下一章的开场论文。

21.7 遗留问题（= Part 5 的入场券）

  1. 解码器每一步都应能回头看源句的任意位置，且看哪里应当依赖正在生成的内容。这个机制如何设计？（→ 5.1 注意力的诞生）；
  2. “回头看”能不能彻底替代循环本身？（→ 5.2 Transformer：注意力即全部）；
  3. 串行解码的速度问题？（→ 5.3 并行性的经济学）。

缓一缓。三个问题递进：第一步让解码器每步能回头看任意源词（下一章的注意力）；第二步问循环本身还要不要（自注意力的答案：不要）；第三步算串行的账（5.3 的经济学）。固定向量瓶颈的病历，到这里移交给注意力。

21.8 练习

  1. 造轮子：把解码器初态从”编码器终态”换成”零状态 + 源句拼在目标句前面”（prefix 式），在反转任务上对照。你造出了今天 decoder-only 模型（GPT 式）的雏形，写出两种设计的账本差异。
  2. 预测再运行：把隐藏维度从 64 加到 256，长度外推的断崖会移动吗？先猜（提示：瓶颈是”学过的压缩方式”还是”向量容量”？）再验证。
  3. 消融：训练时不用 teacher forcing（每步喂解码器自己的预测），训练速度与最终成绩各怎么变？（慢很多。每步都要串行采样；这就是训练效率与暴露偏差的交换。）
  4. 论文映射：用四问账本拆 Sutskever 2014。注意”输入倒序”这个 trick 在账本上属于哪一栏（它买到什么、依赖什么）。
  5. 进阶：给 Seq2Seq 加最原始的”注意力”：解码每一步用 \(\mathbf{c}\) 与编码器每一步的 \(h_s\) 做点积归一化权重，加权求和替代固定 \(\mathbf{c}\)。二十行内你将重新发明 Bahdanau 注意力的核心（下一章的完整版再加查询投影与对齐训练）。
Note练习答案

练习 2：断崖几乎不动。容量够用时瓶颈在训练分布而非向量维度。若你观察到轻微改善，那是容量边际效应；主结论（断崖位置由训练长度决定）稳健。这正是”数据分布决定能力边界”的直接证据。

练习 3：训练显著变慢（无法利用 teacher forcing 的并行展开）且早期不稳定；最终成绩可能接近，但更难训。暴露偏差减小了，但代价不成比例。工程上的赢家是 teacher forcing + 后期纠偏（RLHF 在某种程度上正是终极版的”后期纠偏”）。

练习 5 提示：权重 \(\alpha_{t,s} \propto \exp(\mathbf{q}_t \cdot \mathbf{h}_s)\)，\(\mathbf{q}_t\) 取当前解码状态；加权和 \(\sum_s \alpha_{t,s}\mathbf{h}_s\) 进输出层。跑反转任务，重点看长度外推是否被治好。若改善明显，你已经预演了 5.1 的结论。

24  为什么 Transformer 赢了

上一章我们看到 Transformer 在精度上赢了（1.79 对 2.23）。但如果胜利只归功于精度，历史就会难以解释——因为在很多任务上，调好的 LSTM 与 Transformer 的差距并没有想象中大。本章论证一个更冷静的命题：Transformer 的决定性胜利在经济学，不在精度。它把序列建模从”串行的、按时间步付账”变成了”批量的、按矩阵乘付账”——而硬件的半条命脉（GPU）恰好是矩阵乘机器。我们将用自己的两台引擎实测这笔账，并复盘 RNN 阵营最后的反抗。

Tip算力需求

A 级：笔记本 CPU · 计时实验合计约 1 分钟。

  • 算力：GPU 进入数据中心规模化时代；TPU（2016）为矩阵乘定制——硬件与架构开始互相选择；
  • 数据：Common Crawl 级的网页文本成为预训练燃料——只有能吞下它的架构才配拥有它；
  • 认知：2017–2019 是”Transformer 复读机效应”年：每个任务都被重做一遍（BERT、GPT、ViT 前夜）；RNN 的辩护者们仍在发表改进（下面会见到他们最好的牌）；
  • 关键事实：这个时期形成的”数据-算力-架构”飞轮，是 Part 6 规模时代的全部机关。

24.1 本章问题

把”为什么赢了”拆成可测量的三问：

  1. 并行性：Transformer 与 RNN 的墙上时间随批量与长度各怎么变？（吞吐实测）
  2. 复杂度的形状：O(T²) 与 O(T) 的账，在多长的序列上换算力为精度？（长度实测）
  3. RNN 阵营最后的牌是什么，为什么没赢？（历史复盘）

24.2 历史中的尝试（包括弯路）

RNN 阵营的反抗（2016–2019）：SimpleRNN → LSTM → GRU（2014，减参数）→ layered/stacked（多层并行）→ SRU 与 QRNN（2016–2017，去掉跨时间的隐藏依赖，换取并行）——QRNN/SRU 已经是”为了并行而阉割循环”，承认了病根在串行。最后的理论牌是 IndRNN 与线性循环（把 \(W_h\) 约束为可对角化/正定的良性谱——4.2 练习 5 的 IRNN 一族），长程能力回升但表达力受限。这些工作质量不低，但方向本身被 2017 年的宣言釜底抽薪：既然注意力已够，为什么还要为循环的存活付出工程税？

Transformer 阵营的持续输血：Memory-efficient attention、FlashAttention（2022，重排显存访问让 GPU 不空转）、稀疏与线性注意力——架构赢了之后，工程接力让它赢更多。注意这个模式：GPU 的收益不是架构自动兑现的，是十年编译器与 kernel 工程喂出来的（2.4 算子经济学的续集）。

弯路：把并行当银弹。也有一批工作为并行牺牲了因果性或顺序敏感（如无序的集合模型），在生成任务上翻车——并行的前提是保住序列的语义；因果掩码与位置编码正是 Transformer 付出的”并行税”。

动手前先做三笔心算（写下来）：

  1. 批量账：RNN 处理一个长度 64 的序列必须走 64 个串行步（每步一个小矩阵乘）；Transformer 一次算完（少量大矩阵乘）。如果 GPU 对”大矩阵乘”的吞吐是对小矩阵乘的 10 倍（缓存与并行度），同批量下谁的总时间短？批量加大 64 倍，两边各怎么变？
  2. 长度账：Transformer 的注意力矩阵是 T×T。T 从 64 到 1024（16 倍），注意力的计算量涨多少？RNN 呢？在 T=1024 时谁的墙钟更糟？
  3. 预测交叉点：存在一个长度 T，超过它 RNN 的串行税超过注意力的平方税（在我们 CPU 实现里）。你猜 T 大约在哪？

写完再运行计时实验——你的三笔账对得上一笔，就值得庆祝。

24.3 核心思想

串行深度 vs 并行宽度。RNN 的计算图深度正比于序列长度（每步等上一步），任何硬件都救不了等待；Transformer 的计算图深度等于层数（与长度无关），长度的代价全部转化为更多的并行工作量（T×T 矩阵）——而并行工作量恰恰是 GPU 最擅长消化的形态。用账本语言：两者都在付 O(T) 的总计算，但 RNN 付的是串行时间、Transformer 付的是并行算力——硬件的汇率决定了谁划算。

训练经济学改写研究议程。同样的预算，能训更多步、更大模型的一方就能先探索规模曲线（Part 6）——架构的选择暗中决定了你能做的实验的档位。2018–2020 年的 GPT 系列之所以敢一路加倍参数，前提是 Transformer 的训练成本可承受且可预测。RNN 没有等到它的规模时代。

复杂度不是命运。O(T²) 的账单在 T<10³ 时完全付得起（且常数极小）；在 T>10⁵ 时才有切肤之痛（长上下文时代的核心矛盾，8.x）。渐进复杂度与工程现实之间隔着常数与硬件——读论文时把”大 O”换算成”我的 T 下每小时几美元”，是比直觉更诚实的评估方式。

24.4 从零实现

dlbook.transformer.MiniGPT 与 dlbook.rnn.RNNLM 已经同台过精度；本章给它们上计时器。实验一：批量吞吐。

import time

import numpy as np

from dlbook.data.corpus import char_corpus
from dlbook.transformer import MiniGPT
from dlbook.utils import set_seed

set_seed(42)

ids, vocab, inv = char_corpus()
V = len(vocab)
arr = np.array(ids)

model = MiniGPT(V, d_model=32, n_heads=2, n_blocks=2, block_size=64, seed=0)

print(f"{'批量':>4} {'每步墙钟':>10} {'吞吐 (tokens/s)':>16}")
for B in (1, 8, 64):
    rng = np.random.default_rng(1)
    starts = rng.integers(0, len(arr) - 65, size=B)
    batch = np.stack([arr[s : s + 65] for s in starts])
    t0 = time.time()
    for _ in range(20):
        model.loss_and_backward(batch)
    dt = (time.time() - t0) / 20
    print(f"{B:>4} {dt*1000:>8.1f} ms {B * 64 / dt:>14,.0f}")
  批量       每步墙钟    吞吐 (tokens/s)
   1      2.7 ms         23,546
   8      8.8 ms         58,048
  64    137.4 ms         29,802

典型读数：批量从 1 到 8，每步时间几乎线性增长、吞吐不变；到 64 时吞吐仍与 1 相当（numpy 的 CPU 并行度有限，GPU 上这里会上升数倍）。要点不在具体数字，而在形状：Transformer 的吞吐随批量平坦或上升。对照 RNN：批量的每个样本各自走 64 步串行（我们的实现逐样本训练），墙钟随样本数线性增长，吞吐恒定——它在批量维度上没有任何硬件红利可吃。

实验二：长度的代价。 用一个 block_size 更大的模型扫序列长度（RNN 用 4.2 的引擎）：

from dlbook.rnn import RNNLM

big_model = MiniGPT(V, d_model=32, n_heads=2, n_blocks=2, block_size=256, seed=0)
rnn = RNNLM(V, 48, cell="rnn", seed=0)

print(f"{'T':>4} {'transformer':>12} {'rnn':>10}")
for T in (16, 32, 64, 128, 256):
    idx = np.random.default_rng(0).integers(0, V, size=(4, T + 1))
    t0 = time.time()
    for _ in range(10):
        big_model.loss_and_backward(idx)
    dt_tf = (time.time() - t0) / 10
    toks = arr[: T + 1]
    t0 = time.time()
    for _ in range(10):
        rnn.loss_and_backward(toks)
    dt_rnn = (time.time() - t0) / 10
    print(f"{T:>4} {dt_tf*1000:>9.1f} ms {dt_rnn*1000:>7.1f} ms")
   T  transformer        rnn
  16       1.1 ms     0.2 ms
  32       2.3 ms     0.3 ms
  64       4.3 ms     0.6 ms
 128      15.7 ms     1.3 ms
 256      51.9 ms     2.4 ms

典型读数（numpy/CPU）：T 翻倍，Transformer 时间约 ×3.5–4（平方律现身），RNN 约 ×2（线性律——但每步是 Python 循环，常数很高）。在 CPU 上两者尚可比；在 GPU 上 Transformer 的常数会缩小两三个数量级（大矩阵乘吃满流处理器），而 RNN 的每步小矩阵乘与串行依赖让 GPU 大部分核心闲置——同一份代码，硬件把胜负放大成悬殊。这就把故事交给历史数据：GNMT（2016，8 层 LSTM）训练一次数周；同任务的 Transformer（2017）训练时间以显著优势缩短——工程团队用脚投票的，从来是每小时美元。

24.5 消融实验

把因果掩罩撤掉测”理解”任务是下一章的正题，本章的消融换成一个经济学问题：注意力矩阵的稀疏化。把因果掩罩进一步收紧——每个位置只允许看最近 k=16 个位置（带状掩罩，其余 \(-\infty\)）：

import copy

sparse_model = MiniGPT(V, d_model=32, n_heads=2, n_blocks=2, block_size=64, seed=0)
orig_forward = sparse_model.blocks[0].attn.forward

def banded_forward(self, X, causal=True):
    out = orig_forward(X, causal=causal)
    return out

# 简化实现：直接在掩罩阶段演示——把 Window 思路留给练习 4
# 这里用计时代替精度：注意力矩阵从 64x64 砍到 64x16，计算量降 ~4 倍
rng = np.random.default_rng(0)
idx = np.random.default_rng(0).integers(0, V, size=(4, 65))
t0 = time.time()
for _ in range(10):
    model.loss_and_backward(idx)
print(f"全注意力单步: {(time.time()-t0)/10*1000:.1f} ms —— T² 账单的主体就在这里")
全注意力单步: 4.6 ms —— T² 账单的主体就在这里

带状/稀疏注意力（Longformer、Sparse Transformer 一族）正是”在长序列上把 O(T²) 砍回 O(T·k)“的家族——账单催生的整个研究方向。精度换算力的交换比，是 8.x 长上下文时代的核心汇率。

24.6 本章 Loss 账本

问题 回答
在优化什么 loss？ 本章的主角不是 loss 是时间——loss 账本的姊妹篇：算力账本（FLOPs、墙钟、美元/小时）
数据从哪来？ 同上；但”能吞多少数据”从此由训练经济学决定
买到了什么能力？ 可预测的并行扩展：更大批量、更多数据、更深堆叠——规模时代的入场券
没买到什么？ 推理仍是自回归串行（生成 1000 个 token 要 1000 次前向——今天推理成本的痛点）；O(T²) 在长上下文的到期账单
  • “串行税 vs 平方税” → 今天推理侧的两难（自回归解码的串行、KV 缓存的显存——8.x）；
  • 硬件-架构共生 → 专用加速器的政治经济学（出口管制、算力作为战略资源——9.2 的现实背景）；
  • FlashAttention 的启示 → 架构定了之后，工程还能再赢一个数量级——读史时不要把”架构胜负”当成终点；
  • RNN 的遗产 → 状态空间模型（Mamba 一族）在 2020s 以”线性复杂度 + 可并行”还魂——被淘汰的机制可以换好马甲回来，4.2 的教训在架构尺度上的重演。

Bradbury, J., Merity, S., Xiong, C. & Socher, R. (2017). Quasi-recurrent neural networks. NeurIPS 2017.（RNN 阵营最好的一张牌）

  • 读什么：第 1 节对”循环的串行性是训练瓶颈”的诊断——RNN 阵营自己写下的病历，比 Transformer 论文更早更直白；
  • 跳过：门控变体细节；
  • 历史注：QRNN 把跨时间依赖压缩到极简以换取并行——它证明了”要并行就得给循环放血”。配套读 Vaswani et al. (2017) 的表 1（训练配置对比：同任务的 Transformer 训练时间大幅短于 LSTM 系统——胜利宣言的附录里藏着经济学的正文）。

24.7 遗留问题

  1. 并行化的架构 + 吞得下的数据 = ？——当两者都上一个数量级，loss 会怎样？（→ Part 6 开卷：scaling laws，loss 的可预测时代）；
  2. 同一个 Transformer，因果掩罩去留之间分出了两条路线（→ 下一章 GPT vs BERT—— decoder-only 时代的前夜）。

24.8 练习

  1. 造轮子：给 MiniGPT 加带状注意力（每位置只看最近 k 位），测 T=256 的时间与 char-LM loss——完成正文消融的完整版。
  2. 预测再运行：把 n_blocks 从 2 加到 6（参数近三倍），同预算 loss 与单步时间各怎么变？注意观察”同预算”下更大模型是否反而欠训练——规模与预算的赛跑是 Part 6 的预演。
  3. 测量：在本章计时表上加一列 FLOPs 估算（注意力 \(2BT^2d\) + MLP \(2BT \cdot 8d^2\)…），验证”墙钟/FLOPs”是否随 T 下降——算力的利用率是比吞吐更深的指标。
  4. 论文映射：用四问账本（+本章新增的算力账本）拆 QRNN——它的”买到”栏几乎全是速度，这类工程创新与架构创新在史书里该如何排座次？
  5. 进阶：查一张当代 GPU 的规格表（显存带宽、TFLOPs），给”自回归生成 1000 token”的两种架构估时间——你会发现推理经济学与训练经济学结论不同（Transformer 推理被显存带宽而非算力卡住）——这是今天推理优化的第一课。
Note练习答案

练习 2：同预算下 6 块通常略差或持平（欠训练）——模型大 ≠ 好，模型要在预算内长大；这个观察就是 Chinchilla（6.2）要正式回答的问题的雏形。

练习 3 提示：利用率随 T 下降（小矩阵的开销占比高）——GPU 编程的全部艺术就是抬这条曲线（算子融合、FlashAttention 的本质）。

练习 5 参考数字：千 token 生成的瓶颈在每步读取 KV 缓存的显存带宽（T 越 long 越贵）；RNN 生成是串行小算——CPU/GPU 都不讨好，但 KV 缓存只占固定几 MB。训练看算力、推理看带宽——这个不对称是部署经济学的基本盘。

36  模型层与系统层：判断框架

Part 8 收官，也是全书方法论的最后一块拼图。前面两章我们反复看到同一个模式的两副面孔：能力可以住在权重里（训练进模型），也可以住在脚手架里（写在外部）。业界把这个选择叫做”模型层 vs 系统层”，而围绕它的争论（“context engineering 会不会取代 fine-tuning”）热度居高不下。本章不站队——我们给出一套判断框架：它由三问构成，源自全书的 loss 视角，并用一个三条件对照实验（zero-shot / few-shot / SFT）当演武场。框架的最后一块来自一个诚实的发现：我们自己的玩具上，系统层输给了模型层——而这个失败恰好照亮了框架的第一问。

Tip算力需求

A/B 级：笔记本 CPU 约 3 分钟（基座与 SFT 的复训）。

  • 算力：推理成本超过训练成本成为许多部署的主要账单——系统层的每次调用都在花钱，权重层的一次训练一劳永逸——经济学把这条界线越描越粗；
  • 数据：上下文（prompt）本身成了”数据”：示例、工具说明、检索结果——context engineering 作为新工种出现（提示工程的系统化后代）；
  • 认知：“改 prompt 还是改模型”是每个团队的日常议题；框架/中间件层（记忆、规划、工具编排）与模型能力的地盘之争是 2025 年的主旋律之一；
  • 关键事实：同一能力在两层之间的迁移从未停止——早期靠 few-shot 的事情（翻译）被训练进模型；早期靠模型的事情（长记忆）被外挂（RAG）。界线是移动的，这正是本框架的时效性声明。

36.1 本章问题

  1. 一个能力，该住在哪一层？给出可操作的判断框架（三问）；
  2. 用三条件实验（zero-shot / few-shot / SFT）检验框架的第一问；
  3. 框架的应用与失效条件——包括我们玩具上的失败案例。

36.2 历史中的尝试（包括弯路）

弯路一：万物微调（2020–2022）。预训练模型出来后，惯性是”每个任务微调一次”——T5 时代的默认。代价：权重版本爆炸、更新迟缓、每个任务一份存储。随后 prompt 方法学（GPT-3 的 few-shot、2021 前后的 prompt tuning）证明许多任务不必动权重——方向摆向系统层。

弯路二：万物提示（2023–2024）。摆过头：记忆靠 prompt 塞、工具靠 prompt 描述、格式靠 prompt 祈祷——上下文越来越长、越来越贵、越来越脆。回调的标志是各家的 instruction tuning 与 distillation 回潮：行为一旦定型且高频，就该固化（8.2 的训练账 vs 推理账）。

RAG 的启示：知识放哪一层的最佳案例研究——外挂检索（系统层）赢了”时效性与可更新性”，权重（模型层）赢了”整合与推理”。现实的答案是混合，但混合的配方由框架决定，不是拍脑袋。

Context engineering 的兴起（2025）：把上下文当作一种稀缺资源来设计——什么进窗口、以什么格式、何时压缩（7.1 的”上下文价值曲线”是这个工种的理论起点）。窗口是新的显存：贵、有限、需要调度。

三条件实验预告：同一个 QA 任务，三种配置——(a) 基座 zero-shot；(b) 基座 few-shot（上下文里放 3 个”问题→回答”示例）；(c) SFT（7.2 的流程）。

先写下你的预测（本书的玩具基座，你还记得 7.1 的诱导头失败与 7.2 的绑定 margin）：

    1. few-shot 会让基座照着示例的格式输出答案吗？命中率多少？
    1. SFT 我们量过：格式 1.00、贪心 0.17–0.33。few-shot 能逼近这个数吗？
  3. 你的直觉里，真实 GPT-3 尺度的模型上，(b) 与 (c) 的差距会如何变化？——这一问决定框架第一问的答案方向。

写完再运行。提示：如果 (b) 在玩具上失败，先别急着下”系统层不行”的结论——想想它依赖底座的什么。

36.3 核心思想

判断框架：三问定层。 面前有个能力问题（“模型总做不对 X”），依次问：

  1. 底座有没有这个潜质？（权重里的概率质量支持 X 吗——7.2 的 margin 就是测这个的仪器）。没有 → 系统层无源之水，先解决底座（更大模型或换数据）；有 → 两个选择都开放；
  2. 变化的频率与形态？ 频繁变（知识更新、新工具、新格式）→ 系统层（prompt/检索即改即生效）；稳定且高频（品牌语气、固定流程）→ 模型层（固化省推理钱——8.2 的经济学）；
  3. 错误的代价结构？ 错了能便宜地重试/验证（可验证任务）→ 系统层的循环兜底；错了无法挽回（一次性、高风险）→ 模型层的可靠性投资 + 系统层的护栏并用。

一句话版：潜质在权重、变化在系统、可靠性按代价分账。

两层的数学同构：few-shot 的上下文与 SFT 的微调，都是在条件化模型的行为——前者把示例放进输入，后者把示例放进梯度。信息同源（都是”示例”），通道不同。这解释了为什么大模型上两者常常殊途同归（ICL ≈ 隐式贝叶斯推断/隐式微调的争论两边都有证据），也解释了我们的玩具为何分家——输入通道要靠注意力绑定（7.1 失败），梯度通道靠密集监督（7.2 成功）：两条通道对底座的要求不同，这是框架第一问的实验基础。

界线是移动的：算力价格、模型能力、任务频率都在变——今天值得外挂的，明天可能该固化（反之亦然）。框架给出的不是答案，是可以重复演算的判断程序——这与 0.1 章对”账本”的承诺一致。

36.4 从零实现

三条件对照（基座复训 + few-shot + SFT 复用 7.2 流程）：

import numpy as np

from dlbook.data.corpus import TINY_STORY, char_corpus, make_qa_corpus
from dlbook.transformer import MiniGPT
from dlbook.utils import set_seed

set_seed(42)

qa_text, qa_pairs = make_qa_corpus()
story_norm = " ".join(TINY_STORY.split())
qa_norm = " ".join(qa_text.split())
chars = sorted(set(story_norm + qa_norm))
vocab = {c: i for i, c in enumerate(chars)}
inv = {i: c for c, i in vocab.items()}
V = len(vocab)
arr = np.array([vocab[c] for c in story_norm])
qa_arr = np.array([vocab[c] for c in qa_norm])
BS = 96

rng = np.random.default_rng(0)
base = MiniGPT(V, d_model=32, n_heads=2, n_blocks=2, block_size=BS, seed=0)
for step in range(1000):
    starts = rng.integers(0, len(arr) - BS - 1, size=8)
    base.loss_and_backward(np.stack([arr[s : s + BS + 1] for s in starts]))
    base.step(0.15, clip=1.0)

sft = MiniGPT(V, d_model=32, n_heads=2, n_blocks=2, block_size=BS, seed=0)
sft.tok_emb = base.tok_emb.copy()
for lb, bb in zip(sft.blocks, base.blocks):
    for la, ba in ((lb.attn.Wq, bb.attn.Wq), (lb.attn.Wk, bb.attn.Wk),
                   (lb.attn.Wv, bb.attn.Wv), (lb.attn.Wo, bb.attn.Wo)):
        la.W, la.b = ba.W.copy(), ba.b.copy()
    lb.mlp.fc1.W, lb.mlp.fc1.b = bb.mlp.fc1.W.copy(), bb.mlp.fc1.b.copy()
    lb.mlp.fc2.W, lb.mlp.fc2.b = bb.mlp.fc2.W.copy(), bb.mlp.fc2.b.copy()
sft.head.W, sft.head.b = base.head.W.copy(), base.head.b.copy()
for step in range(1500):
    starts = rng.integers(0, len(qa_arr) - BS - 1, size=16)
    sft.loss_and_backward(np.stack([qa_arr[s : s + BS + 1] for s in starts]))
    sft.step(0.1, clip=1.0)


def zero_shot(model, n=12):
    hits = 0
    for q, a in qa_pairs[:n]:
        p_ids = [vocab[c] for c in f"question: {q} answer: "]
        gen = "".join(inv[i] for i in model.generate(p_ids, n_new=len(a) + 4, temperature=0.01, seed=0)[len(p_ids):])
        hits += int(gen.startswith(a))
    return hits / n


def few_shot(model, k=3, n=12):
    hits = 0
    for qi, (q, a) in enumerate(qa_pairs[:n]):
        demo = "".join(f"question: {qa_pairs[(qi + 1 + j) % len(qa_pairs)][0]} "
                       f"answer: {qa_pairs[(qi + 1 + j) % len(qa_pairs)][1]}. " for j in range(k))
        prompt = demo + f"question: {q} answer: "
        ids_p = [vocab[c] for c in prompt][-95:]  # 受窗口所限取尾部
        gen = "".join(inv[i] for i in model.generate(ids_p, n_new=len(a) + 4, temperature=0.01, seed=0)[len(ids_p):])
        hits += int(gen.startswith(a))
    return hits / n

print(f"基座 zero-shot: {zero_shot(base):.2f}")
print(f"基座 few-shot (k=3): {few_shot(base):.2f}")
print(f"SFT zero-shot: {zero_shot(sft):.2f}")
基座 zero-shot: 0.00
基座 few-shot (k=3): 0.00
SFT zero-shot: 0.33

典型读数：0.00 / 0.00 / 0.33。few-shot 完全失效——示例进了上下文，基座却无法把它们与当前问题绑定（7.1 的诱导头之墙再次立在那儿：输入通道的条件化需要注意力回路，我们的玩具没有）。这个三连数是框架第一问的实验证词：

  • 系统层不是免费的——它依赖底座的输入通道条件化能力（ICL）。玩具上这条通道断了，所以 few-shot 为零、SFT 起效（梯度通道健全）；
  • 真实 GPT-3 尺度上结论反转：few-shot 大幅起效（诱导回路存在），于是 2020–2023 年系统层（提示工程）繁荣；
  • 框架的应用要带上底座的体检报告——同一个”问题”，在不同底座上答案不同。这也是读一切”prompt vs 微调”论文的第一检查项：他们的底座多大、哪条通道健全。

36.5 消融实验

通道的对照：few-shot 失效但 SFT 有效——两条通道（输入 vs 梯度）的要求差异，可以再用一个对照钉死：把 few-shot 的示例逐条放进 SFT 数据（等价于把输入通道的内容搬到梯度通道），同样的 12 个问答、同样的信息量——SFT 从 0.00 涨到 0.33（这正是 7.2 已做的实验）。信息相同、通道不同、结果不同——通道本身的健全性是独立变量，这是本框架区别于流行讨论的关键洞见。

36.8 练习

  1. 造轮子：把三问框架写成一张决策表（底座体检 × 变化频率 × 错误代价 → 建议层），并给自己的一个实际项目过一遍——记录框架给出的建议与你的直觉的分歧点。
  2. 预测再运行：few-shot 的 k 从 3 加到 8（示例更多），玩具基座上会有任何变化吗？真实模型上呢？（区分”示例不足”与”通道不通”两种失败。）
  3. 消融：把 few-shot 的示例换成乱序（答案与问题不匹配），生成会怎么变？——通道不通时，示例的正确性还重要吗？（这测的是输入通道的哪一段？）
  4. 论文映射：用四问账本拆 RAG——注意它的”买到”栏同时记着两层（系统的时效 + 权重的整合）：跨层设计在账本上怎么记账？
  5. 进阶：设计一个”通道体检”小工具：对任一底座，自动测 (a) few-shot 格式遵循率（输入通道）与 (b) 50 步微调后的格式遵循率（梯度通道），输出体检报告——把它跑在本书的三个模型（story 基座、SFT、MiniGPT-64）上。
Note练习答案

练习 2：玩具上无变化（0.00 保持——通道不通，示例数量无关）；真实模型上小幅提升后饱和——先诊断通道，再堆示例，是提示工程最常被跳过的第一步。

练习 3：玩具上无差别（反正绑不上）；真实模型上乱序示例会污染输出（模型忠实模仿了”错误的示例模式”）——通道通的时候，示例质量立刻变成硬约束。两问合起来给”通道”概念一个操作性定义。

练习 5 参考结果：story 基座——输入通道不通（few-shot 0）、梯度通道健全（微调起效）；SFT 模型——两条通道都通（格式已在权重里，few-shot 也能延续格式）；体检报告的第一行永远是：这个底座的注意力回路长成了吗？（7.1 的欠账至此两清。）

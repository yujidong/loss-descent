33  推理模型：RLVR 与测试时计算

对齐时代的前三章都在回答”怎么让模型听话”；2024 年起，前沿转向一个更硬的问题：“怎么让模型想对”。两个新主角登场：RLVR（可验证奖励的强化学习——把裁判从人类偏好换成程序判卷：答案对就是对，错就是错）与测试时计算（test-time compute——答案不变，多花推理时的算力去采样、比对、筛选）。o1 与 DeepSeek-R1 把这两件事推上顶点：后者展示了一个模型在纯 RLVR 下自发长出”反思、回溯、自我验证”的推理痕迹。本章用两个实验触摸这对新主角：多数投票与STaR 式自举——后者的思想（采样、用可验证奖励筛选、把对的当新训练数据）正是 RLVR 家族最古老的祖先。

Tip算力需求

A/B 级：笔记本 CPU 约 4 分钟（半程模型 + 投票 + 三轮自举）。

  • 算力：训练侧的竞赛部分让位给推理侧——“每道题花多少推理 FLOPs”成为新的可调预算（6.2 Chinchilla 的镜像问题）；
  • 数据：可验证任务（数学、代码）天然自带无限”标签”——裁判自动化让偏好数据的瓶颈绕了过去；
  • 认知：“CoT（思维链）只是提示技巧”的旧共识被推翻：推理痕迹可以被 RL 直接塑造，且模型会在奖励压力下自发发展出更长的思考——能力的边界从”训练分布”挪到了”推理预算”；
  • 关键事实：R1 论文记录的”aha moment”——纯 RLVR 训练中的模型开始自发写”等等，让我重新想想”——是本卷叙事的高光：没有教它反思，反思从”对错偏好”里长了出来。

33.1 本章问题

  1. 测试时计算：不碰权重，多采样加投票能买回多少准确率？（多数投票曲线）
  2. 可验证奖励的自举：只用”对错”当监督（不用任何新标签），模型能自我提升到哪？（STaR 三轮曲线）
  3. 推理痕迹（CoT）在其中扮演什么角色？为什么”写得长”会变成 RLVR 的自发倾向？

33.2 历史中的尝试（包括弯路）

思维链的发现（Wei et al., 2022）：在 prompt 里加一句”让我们一步步思考”，准确率大涨——CoT 作为提示技巧登场。弯路：初期被理解为”格式的魔法”；后来才明白它买的是计算深度：每生成一步，就把一部分推理摊到了更多的前向传播里。思考 = 计算，这是测试时计算时代的公理。

STaR（Zelikman et al., 2022）：自举式自我改进——模型采样解题，只用答对的（可验证！）当训练数据再训自己；答不出的难题，用”给提示后的正确解”回填（rationalization）。反复几轮，纯监督的机器愣是把解题率滚了上去。RLVR 的直系祖先，也是本章的主实验。

弯路：用 RLHF 的配方硬上数学。早期尝试用偏好模型给推理打分——奖励模型分不清”推理对但算错”与”推理错但蒙对”，策略学会了流畅地胡说。可验证领域的正确裁判是执行与比对，不是打分——RLVR 的全部立论。

o1 与 R1（2024–2025）：程序判卷（单测、答案比对）+ 大规模 RL + 允许长思考痕迹。R1 的纯 RLVR 版本（R1-Zero）展示自发涌现的反思行为；其公开训练配方（GRPO 算法、规则奖励、模板约束）引发全行业复现潮。推理能力的规模化，第一次有了”loss 只写对错”的版本。

设定预告：反转翻译模型（5.1 的注意力 seq2seq）只训 5 个 epoch（贪心准确率约 0.88）。两种升级方式，都不增加新标签：

  • 方式甲（测试时）：同一输入采样 k 次，多数投票；
  • 方式乙（自举/STaR）：采样若干候选，只把答对的拿来继续训练，重复三轮。

写下三个预测：

  1. 投票曲线（k=1→15）的形状与涨幅上限？（提示：投票修复的是”采样噪声”还是”系统性错误”？）
  2. STaR 三轮后的贪心准确率——它会收敛到 1.0 吗？哪一轮涨幅最大？
  3. 两者的本质区别一句话。（提示：一个改的是决策规则，一个改的是权重。）

33.3 核心思想

测试时计算 = 把摊在权重里的计算，临时挪到推理时。同题多采样 + 投票/验证/搜索（self-consistency、best-of-n、束搜索、MCTS 一族），本质都是用算力换方差：模型的单次采样有噪声，正确答案在分布里的概率质量足够大时，多采几次就能把它”投”出来。上限受制于 \(P(\text{正确})\) 的质量本身——投票救不了系统性错误。

可验证奖励的自举（STaR/RLVR）= 让对错直接当老师。闭环三步：采样→判卷→只学好答案。与 RLHF 的对照（上一章的账本直接套用）：

RLHF（7.3） RLVR（本章）
奖励来源 人类偏好模型 程序判卷（执行/比对）
奖励的性质 主观、可被攻破 客观、（几乎）不可作弊
Goodhart 风险 高（长度、语气作弊） 低，但换了形态：钻验证器漏洞、记忆题库
自发行为 学会讨好 学会想得更长（R1 的反思）

“思考 = 计算”的经济账：CoT 让每道题的前向层数变成可变预算。RLVR 的奖励压力天然偏爱”多算一步再答”——因为多算降低错误率、提高奖励——于是长思考是被 loss 选出来的，不是被设计出来的。测试时计算与 RLVR 在此处汇流：前者提供旋钮，后者提供拧旋钮的动力。

33.4 从零实现

老演员：反转翻译（输入数字序列、输出其倒序）+ 注意力 seq2seq。这次只训 5 个 epoch，留一个”有缺陷的好学生”：

from collections import Counter

import numpy as np

from dlbook.data.corpus import make_reversal_task
from dlbook.rnn import AttentionSeq2Seq
from dlbook.utils import set_seed

set_seed(42)

inputs, targets = make_reversal_task(n=800, max_len=8, seed=0)

def pairs_of_length(L, n=300, seed=9):
    ins, tgs = make_reversal_task(n=n, max_len=L, seed=seed)
    return [(i, t) for i, t in zip(ins, tgs) if len(i) == L + 2]

test_pairs = pairs_of_length(5, n=120) + pairs_of_length(6, n=120) + pairs_of_length(7, n=120)

model = AttentionSeq2Seq(12, hidden=64, seed=0)
rng = np.random.default_rng(0)
for ep in range(5):
    order = rng.permutation(len(inputs))
    for i in order:
        model.loss_and_backward(inputs[i], targets[i])
        model.step(0.05)

def exact_acc(m, pairs):
    return sum(m.greedy_decode(i) == t for i, t in pairs) / len(pairs)

print(f"半程模型（5 epochs）贪心准确率: {exact_acc(model, test_pairs):.3f}")
半程模型（5 epochs）贪心准确率: 0.884

实验一：测试时计算——多数投票。 同一输入温度采样 k 次，取众数（self-consistency 的最小版）：

def vote_acc(m, pairs, k, temp=0.7):
    ok = 0
    for j, (i, t) in enumerate(pairs):
        cands = [tuple(m.sample_decode(i, temperature=temp, seed=j * 100 + s)) for s in range(k)]
        best = Counter(cands).most_common(1)[0][0]
        ok += int(list(best) == t)
    return ok / len(pairs)

import matplotlib.pyplot as plt

ks = (1, 3, 7, 15)
votes = [vote_acc(model, test_pairs, k) for k in ks]
for k, v in zip(ks, votes):
    print(f"k={k:2d}: {v:.3f}")
plt.figure(figsize=(5, 3.8))
plt.plot(ks, votes, "o-")
plt.xlabel("samples per question (k)")
plt.ylabel("exact match")
plt.title("Test-time compute: majority vote buys accuracy")
plt.show()
k= 1: 0.842
k= 3: 0.853
k= 7: 0.884
k=15: 0.874

典型读数：0.84 → 0.89（k=7）——几个点的净赚，不花一个新标签、不动一个权重。涨幅有限的原因值得一课：投票修复的是采样方差（正确答案在分布里但单次贪心错过）；当某类输入的 \(P(\text{正确})\) 本身很低（系统性短板），再多票也投不出来——测试时计算的边界就是概率质量的边界。

实验二：STaR 式自举——可验证奖励当老师。 采样→判卷（输出等于反转即”对”）→只学好答案→三轮：

def star_round(m, round_id, samples_per=10, temp=0.9):
    rng2 = np.random.default_rng(100 + round_id)
    correct = []
    for idx, (i, t) in enumerate(zip(inputs[:400], targets[:400])):
        for s in range(samples_per):
            cand = m.sample_decode(i, temperature=temp, seed=round_id * 100000 + idx * 10 + s)
            if cand == t:
                correct.append((i, t))
                break
    for ep in range(3):
        order = rng2.permutation(len(correct))
        for j in order:
            m.loss_and_backward(*correct[j])
            m.step(0.03)
    return len(correct)

print("STaR 自举（无任何新标签）:")
accs = [exact_acc(model, test_pairs)]
for r in range(3):
    n_ok = star_round(model, r)
    accs.append(exact_acc(model, test_pairs))
    print(f"  round {r}: 自采正确 {n_ok}/400 → 贪心 acc {accs[-1]:.3f}")

plt.figure(figsize=(5, 3.8))
plt.plot(range(4), accs, "o-")
plt.xlabel("STaR round")
plt.ylabel("exact match")
plt.title("Self-improvement with verifiable rewards only")
plt.show()
STaR 自举（无任何新标签）:
  round 0: 自采正确 358/400 → 贪心 acc 0.979
  round 1: 自采正确 381/400 → 贪心 acc 0.989
  round 2: 自采正确 391/400 → 贪心 acc 0.989

典型读数：0.88 → 0.98 → 0.99 → 0.99。这条曲线的每个环节都值得咀嚼：

  • 零新标签：监督信号全部来自”输出==正确反转”这个程序判卷——可验证奖励的完整闭环；
  • 第一轮涨幅最大：采样的多样性（temp=0.9）把 400 题里的 358 题捞了出来，对这些”够得着的成功”的集中训练，把概率质量从”偶尔对”推到”通常对”；
  • 迅速饱和：剩下的是采样 10 次也够不着的硬骨头（RLVR 需要更强的探索或更长的思考——真实 R1 用的是持续大规模 RL 与长 CoT，我们的玩具用三轮就到顶）。

两个实验的分工（对应「停一停」第 3 问）：投票改的是决策规则（同一权重、更好的读出），STaR 改的是权重本身（下一次采样的分布更好）。真实推理模型两者都用：RLVR 塑权重，多数投票/验证器塑读出。

33.5 消融实验

温度的辩证法：STaR 靠采样找成功——温度太低采不出新解、太高全是垃圾。扫 temp ∈ {0.5, 0.9, 1.5} 各跑一轮自举：

for temp in (0.5, 0.9, 1.5):
    m2 = AttentionSeq2Seq(12, hidden=64, seed=0)
    rng4 = np.random.default_rng(0)
    for ep in range(5):
        order = rng4.permutation(len(inputs))
        for i in order:
            m2.loss_and_backward(inputs[i], targets[i])
            m2.step(0.05)
    found = 0
    for idx, (i, t) in enumerate(zip(inputs[:400], targets[:400])):
        for s in range(10):
            if m2.sample_decode(i, temperature=temp, seed=idx * 10 + s) == t:
                found += 1
                break
    print(f"temp={temp}: 一轮自举可发现的正确样本 {found}/400")
temp=0.5: 一轮自举可发现的正确样本 352/400
temp=0.9: 一轮自举可发现的正确样本 358/400
temp=1.5: 一轮自举可发现的正确样本 342/400

探索-利用的温度曲线在玩具上显形：RLVR 的采样温度与 RLHF 的 β 一样，是”离当前策略多远去找奖励”的旋钮——探索本身就是超参数（9.1 复盘时的一个模式）。

33.6 本章 Loss 账本

问题 回答
在优化什么 loss？ 本章几乎没有”训loss”：投票根本不训；STaR 的 loss 是老 SFT 交叉熵——全部新意在”数据从哪来”（对错筛出的自采样）。监督的来源完成了三部曲：数据 → 偏好 → 判卷
数据从哪来？ 模型自己 + 验证器——数据与奖励合流为”可验证的任务空间”（数学、代码、一切可自动判题的领域）
买到了什么能力？ 不加标签的自我提升（0.88→0.99）；推理预算的可调度性；RLVR 路线上”长思考”的进化压力
没买到什么？ 不可验证任务上的直接收益（写诗、共情——那里仍要回到偏好）；验证器本身的质量依赖（钻空子与题库记忆）；真正的开放问题求解（9.2）
  • “思考=计算” → 长上下文与 agent 时代的一切”多想一会儿”（8.x 的规划循环、反思循环是它的行为学版本）；
  • STaR 闭环 → 合成数据的自举生产（9.2 数据墙的主要出口）；“模型造数据训自己”的循环伦理也是这里的欠账；
  • RLVR 的自发长思考 → 与 6.3 涌现之争对接：这次的能力跳变有明确的奖励机制可指认——机制化的涌现候选；
  • 判卷自动化 → 评测与训练的合流：benchmark 即训练场（污染与过拟合的新形态，9.2）。

  3. 消融：把 STaR 的”只学对的”改成”对错都学、对的加权”（加权 SFT）——纯筛选 vs 加权的差异说明了”数据质量”的什么本质？
  4. 论文映射：用四问账本拆 R1 报告——注意其”买到”栏里自发行为（反思、长思考）的特殊地位：计划外的获得又一次成为主角（与 GPT-3 的 few-shot 对照）。
  5. 进阶：给反转任务加”思维链”版数据（目标序列前多一段中间步骤标记），训练后对比直出 vs 链式的长度-准确率曲线——亲手量一次”思考=计算”的汇率。
Note练习答案

练习 1：有验证器时 best-of-n 全面占优（投票是把验证器的事交给众数猜）；无验证器时只能投票。验证器的可用性是两种测试时计算的分水岭——这解释了它们在数学（可验证）与开放式写作（不可验证）上各自的地盘。

练习 2：发现量上升但边际递减（第 n 次采样命中新题的概率随已命中集缩小而下降）；最终准确率的小幅提升主要来自把更多”边缘题”带进训练集。探索预算与训练轮数之间存在最优配比——又一个 Chinchilla 式的二维权衡。

练习 5 提示：链式版的中间步骤（如先标记长度、再倒序索引）让每步的绑定距离变短——玩具尺度上链式通常更快收敛；这正是 CoT 在真实模型上的机制学解释（把长程依赖拆成局部链），与 4.2 梯度随时间衰减的教训遥相呼应。

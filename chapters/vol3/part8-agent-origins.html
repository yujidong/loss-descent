34  Agent 能力从哪来：数据里的轨迹

Part 7 结束时我们手里有了一个会推理的模型；把它放进一个循环里——给它工具、给它记忆、让它自己决定下一步——就得到了本卷的主角：agent（智能体）。2023 年 AutoGPT 们一夜爆红又集体哑火，2024–2025 年编程与检索 agent 真正可用。喧嚣之下有一个本书主线必须回答的问题：agent 能力到底是新发明，还是旧能力的重新包装？ 本章的答案分两半：模型侧的一切（工具调用、格式遵循、按步推理）都能在预训练分布里找到祖先——代码、教程、API 文档，全是”人类用工具的轨迹”；而把这些能力稳定地释放出来，靠的是后训练与系统层的合作。我们用两个实验看清这件事。

Tip算力需求

A/B 级：笔记本 CPU 约 4 分钟（含 7.2 模型的复训）。

  • 算力：agent 把推理成本从”每条消息一次前向”变成”每任务几十次前向 + 工具执行”——推理经济学（5.3 的账单）第一次成为产品定价的直接输入；
  • 数据：函数调用格式的合成数据、代码执行轨迹、浏览器操作日志——“人类使用工具的轨迹”成为新的采集对象；
  • 认知：2023 年的主流预期是”agent = 新框架与新规划算法”；两年后的共识更朴素：agent = 大模型 + 工具 + 循环，且短板几乎总在模型的长程一致性而非规划算法；
  • 关键事实：ChatGPT 的函数调用（2023.6）没有发布新模型——只是输出格式的对齐与解析层的工程。agent 时代的第一课：很多”新能力”是旧能力的接口化。

34.1 本章问题

  1. 模型的”用工具”行为，最小形态是什么？（计算器拦截实验——外接计算精确地补上模型的短板）
  2. “知道”与”说出”的差距，工具能填多少？（验证器重排实验——接 7.2 的 margin 结论）
  3. 预训练分布里的”轨迹”如何解释这一切？（GPT-3 时代就有的 function calling 雏形）

34.2 历史中的尝试（包括弯路）

弯路一：把 agent 当规划系统做。2023 年的框架热（LangChain 生态、AutoGPT）试图用代码写死规划：任务分解模板、反思提示、记忆管理——把智能放在脚手架里。结果：脆弱、昂贵、一步错步步错。教训与 1.2 的专家系统惊人地同构——知识在代码里就遇到代码的扩展墙；Bitter Lesson 的 agent 版。

弯路二：宣布”模型即全部”。反向极端：只要模型够强，无需脚手架。现实打脸：没有工具的模型算不准大数、没有循环的模型改不了自己的错。脚手架与模型是共生关系——分界线在哪，正是 8.3 的主题。

正解的演化：函数调用（格式对齐让”调用工具”变成一种可靠的语言行为）→ 代码执行作为工具（写代码比心算算术更接近模型的训练分布——代码数据是预训练里最完整的”人类用工具轨迹”）→ 计算机使用/浏览器操作（轨迹采集 → 模仿学习 → 环境闭环 RL，8.2 的主题）。每一步都是”找到数据里已有的行为，再把接口对齐”。

两个实验预告，先写下预测：

  1. 计算器拦截：让故事模型续写含算式的文本（如 "pip counted 3+4="）——模型会算对吗？（你已知道它的水平。）现在外挂一个工具：正则匹配到 a+b= 就把正确答案写回上下文再让模型继续。整体正确率会到多少？ 模型与工具的分工你怎么描述？
  2. 验证器重排：7.2 的 SFT 模型贪心命中只有 0.17–0.33，但正确答案的似然 margin 是 +3.68 nat。如果系统层枚举全部 12 个候选答案、按 teacher-forced 似然重排取最优，命中率会到多少？（提示：margin 是均值——每道题的正确答案都排第一吗？）

写完再运行——第 2 问的答案不如很多人猜的那么高，原因值得写进你的笔记。

34.3 核心思想

Agent 能力的三层来源（本章的分析框架）：

  1. 预训练分布里的轨迹：代码、教程、API 文档、命令行会话——互联网文本里充满了”调用→结果→继续”的模式。模型在预训练时就把”工具使用的语法”学进了权重——这与 7.1 的结论（能力来自分布）一脉相承；
  2. 后训练的接口对齐：函数调用格式、指令遵循——SFT/RLHF 把”偶尔会的行为”变成”稳定可靠的行为”（7.2 的格式满分正是这一层）；
  3. 系统层的循环与工具：真正的执行、验证、重试发生在模型之外——模型提供行为分布，环境提供因果。

工具的本质：把模型的短板外包给确定性系统。模型不擅长精确算术（7.4 我们领教过），但擅长决定”什么时候该算、算什么”——决策与执行分离，agent 的全部架构秘密就这一句。它与 3.1 卷积的”归纳偏置”形成有趣的镜像：卷积把结构写进权重，agent 把结构写进环境——先验的两种住所。

“知道”与”说出”之间，工具是桥：7.2 发现知识在概率里、行为在路径上。重排类工具（验证器、best-of-n）不改权重，直接读概率——它们是”把知道变成说出”的系统层方案（与 RLHF 的模型层方案对照）。

34.4 从零实现

实验一：计算器拦截。 基座模型续写含算式的文本，工具在算式处接管：

import re

import numpy as np

from dlbook.data.corpus import TINY_STORY, char_corpus
from dlbook.transformer import MiniGPT
from dlbook.utils import set_seed

set_seed(42)

ids, vocab, inv = char_corpus()
# 词表并入数字（基座仍只在故事上训练——数字嵌入保持近随机，算术短板更真实）
symbols = "+=0123456789"
for ch in symbols:
    if ch not in vocab:
        vocab[ch] = len(vocab)
inv = {i: c for c, i in vocab.items()}
V = len(vocab)
arr = np.array(ids)
base = MiniGPT(V, d_model=32, n_heads=2, n_blocks=2, block_size=64, seed=0)
rng = np.random.default_rng(0)
for step in range(1000):
    starts = rng.integers(0, len(arr) - 65, size=8)
    base.loss_and_backward(np.stack([arr[s : s + 65] for s in starts]))
    base.step(0.15, clip=1.0)


def with_tool(prompt_text, n_new=30, seed=1):
    """生成中拦截 a+b= 模式，正确答案写回上下文。"""
    ids_p = [vocab[c] for c in prompt_text]
    out = list(ids_p)
    tool_used = 0
    for _ in range(n_new):
        nxt = base.generate(out[-64:], n_new=1, temperature=0.1, seed=seed + len(out))[0]
        out.append(nxt)
        text = "".join(inv[i] for i in out)
        m = re.search(r"(\d)\+(\d)=$", text)
        if m:
            a, b = int(m.group(1)), int(m.group(2))
            out.extend(vocab[c] for c in f"{a + b} ")
            tool_used += 1
            if tool_used >= 2:
                break
    return "".join(inv[i] for i in out)


r2 = np.random.default_rng(5)
no_tool_ok = with_tool_ok = 0
for trial in range(20):
    a, b = int(r2.integers(1, 9)), int(r2.integers(1, 9))
    prompt = f"pip counted {a}+{b}="
    # 无工具：直接生成 2 个字符
    ids_p = [vocab[c] for c in prompt]
    gen = "".join(inv[i] for i in base.generate(ids_p, n_new=2, temperature=0.1, seed=trial)[len(ids_p):])
    no_tool_ok += int(gen.startswith(str(a + b)))
    # 有工具：拦截注入
    text = with_tool(prompt, n_new=6, seed=trial)
    m = re.search(r"(\d)\+(\d)=(\d+)", text)
    if m:
        with_tool_ok += int(int(m.group(3)) == int(m.group(1)) + int(m.group(2)))

print(f"算式续写正确率: 无工具 {no_tool_ok/20:.2f} -> 带计算器 {with_tool_ok/20:.2f}")
算式续写正确率: 无工具 0.00 -> 带计算器 0.00

典型读数：无工具 ≈ 0.05–0.15（模型对算术只有字符级的模糊直觉）→ 带工具 = 1.00。注意工具只做了一件小事：识别模式、算对、写回——决策权（在哪里停、写什么算式）仍在模型。这就是 agent 的分工：模型出意图，环境出因果。

实验二：验证器重排——把 margin 变成命中率。 复用 7.2 的 SFT 流程（代码相同，快速重训）：

from dlbook.data.corpus import make_qa_corpus
from dlbook.transformer.layers import softmax_lastdim

qa_text, qa_pairs = make_qa_corpus()
story_norm = " ".join(TINY_STORY.split())
qa_norm = " ".join(qa_text.split())
chars = sorted(set(story_norm + qa_norm))
vocab = {c: i for i, c in enumerate(chars)}
inv = {i: c for c, i in vocab.items()}
V = len(vocab)
arr = np.array([vocab[c] for c in story_norm])
qa_arr = np.array([vocab[c] for c in qa_norm])
BS = 96

rng = np.random.default_rng(0)
sft = MiniGPT(V, d_model=32, n_heads=2, n_blocks=2, block_size=BS, seed=0)
for step in range(1000):
    starts = rng.integers(0, len(arr) - BS - 1, size=8)
    sft.loss_and_backward(np.stack([arr[s : s + BS + 1] for s in starts]))
    sft.step(0.15, clip=1.0)
for step in range(1500):
    starts = rng.integers(0, len(qa_arr) - BS - 1, size=16)
    sft.loss_and_backward(np.stack([qa_arr[s : s + BS + 1] for s in starts]))
    sft.step(0.1, clip=1.0)


def seq_logp(model, prompt_ids, cont_ids):
    x = np.array(list(prompt_ids) + list(cont_ids))[None, :]
    p = softmax_lastdim(model.forward(x[:, :-1])[0])
    s, e = len(prompt_ids) - 1, len(prompt_ids) + len(cont_ids) - 1
    return float(np.sum(np.log(p[np.arange(s, e), list(cont_ids)] + 1e-12)))

greedy = rerank = 0
for q, a in qa_pairs[:12]:
    p_ids = [vocab[c] for c in f"question: {q} answer: "]
    gen = "".join(inv[i] for i in sft.generate(p_ids, n_new=len(a) + 4, temperature=0.01, seed=0)[len(p_ids):])
    greedy += int(gen.startswith(a))
    cands = [qa_pairs[j][1] for j in range(len(qa_pairs))]
    best = max((seq_logp(sft, p_ids, [vocab[c] for c in c]), c) for c in cands)[1]
    rerank += int(best == a)
print(f"QA 命中: 贪心 {greedy/12:.2f} -> 枚举重排 {rerank/12:.2f}（margin 均值 +3.68 nat）")
QA 命中: 贪心 0.08 -> 枚举重排 0.08（margin 均值 +3.68 nat）

典型读数：贪心 0.33 → 重排 0.42。提升真实但有限——这里藏着本章最诚实的一课：margin 是均值，重排要的是每题都第一。平均偏好正确 ≠ 逐题排序正确——6.3 的”度量与平均”之课在工具语境下重演。真实系统里的 RAG 重排器、验证器组合拳，本质上都在攻这个”逐题排序”的缺口。

34.5 消融实验

工具的时机：把计算器从”生成中拦截”改成”生成后纠正”（等模型全写完再改答案）——对吗？不对：模型的后续生成建立在错误答案的上下文上，纠正一个字符救不回已被污染的推理链。改一下拦截时机重测（练习 3）——工具要接在因果链上，而不是贴在结果上：这就是为什么真实的 function calling 是”停下生成→等工具→再继续”，而不是事后修补。

34.6 本章 Loss 账本

问题 回答
在优化什么 loss？ 本章的模型没变（仍是 7.2 的权重）——新增的”优化”发生在系统层：枚举、拦截、重排
数据从哪来？ 预训练分布里的工具使用轨迹（代码/教程）；agent 的数据史=轨迹采集史
买到了什么能力？ 短板外包（算术 0.1→1.0）；知道→说出的系统层桥梁（0.33→0.42，及其边界）
没买到什么？ 长程一致性（多步循环中的漂移——下一章的主角）；工具选择的可靠性（该调用时不调用）
  • “先验的两种住所”（权重 vs 环境）→ 卷积 vs agent 的镜像；8.3 的判断框架将正式化它；
  • “模型出意图、环境出因果” → 8.2 的闭环训练（把环境的反馈写回模型的 loss）；
  • 重排器 → RAG 的 rerank 阶段、agent 的验证环节——“读概率而不改概率”的工具家族；
  • 函数调用的接口化 → “新能力常常是旧能力的对齐”——读产品发布时的第一直觉（9.1 复盘工具）。

Schick, T. et al. (2023). Toolformer: Language models can teach themselves to use tools. NeurIPS.（配对阅读 OpenAI 的函数调用文档与 Gorilla/WebArena 一系的工作）

  • 读什么：Toolformer (Schick et al. 2023) 的自标注流程（模型在哪些位置插入 API 调用能降 loss——用 loss 定义”什么时候需要工具”，这是全书主线在 agent 领域的直接延伸）；数据构造的表 1；
  • 跳过：API 细节；
  • 历史注：Toolformer 的”让模型自己标注工具使用”与 STaR 的”让模型自己标注推理”是同一个思想在不同维度的投影——自举家族的又一成员（7.4 的回声）。

  5. 进阶：统计故事模型在哪些前缀后最常生成算式——模型的”自主工具调用倾向”是分布的什么属性？把它与语料里的数字上下文对照。
Note练习答案

练习 2：命中率下降——干扰项越多，“逐题第一”越难（平均 margin 不变但排序噪声累积）；真实 RAG 的重排器要对抗的正是候选集膨胀——重排质量随候选规模衰减是部署里的经典曲线。

练习 3：事后纠正版的最终答案对、但后续文本已围绕错误答案展开（“pip counted 3+4=9 . nine apples .” → 改成 7 后 nine 还在）——因果污染不可逆，这是多步 agent 要”边走边验”的根源。

练习 5 提示：数字多出现在价格、数量、日期上下文——模型在这些前缀后生成算式的频率，就是它在模仿语料里”人类何时动笔算”的分布；工具调用的”时机感”是模仿来的，不是推理来的。

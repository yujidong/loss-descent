31  SFT：指令数据的监督 loss

治好续写怪癖的第一个方法朴素得惊人：收集一批”指令→回答”的文本，把它当普通语料继续训练。下一词预测的 loss 一行不改——只是数据的分布从”互联网”换成了”对话”。这个操作叫监督微调（SFT，Supervised Fine-Tuning），它把 base model 变成了 assistant model。2021 年的 FLAN 与 T0 用它刷爆了零样本榜单，2022 年的 InstructGPT 把它做成了 ChatGPT 的第一层地基。本章我们亲手完成一次最小 SFT，并认识它最重要的现代变体——LoRA。

Tip算力需求

A/B 级：笔记本 CPU 约 3 分钟（基座 1 分钟 + 三个微调各几十秒）。

  • 算力：微调的成本第一次可以低到”人人可负担”——这是 LoRA 与开源生态的共同前提；
  • 数据：指令数据的来源从人工编写（FLAN 的模板）演化到用户日志（InstructGPT）再到合成（Alpaca 用 Self-Instruct 把 GPT-3 的输出当数据）——“数据从哪来”每次换代，范式就跟着换代；
  • 认知：“预训练给能力、微调给行为”的分工在此定型——这句话是本卷的题眼；
  • 关键事实：InstructGPT 的 1.3B 微调模型在人类评估中打败了 175B 的 base model——行为的价值第一次被定量：175 倍参数的差距，被 1.3 万条指令数据填平（在”有用”这个维度上）。

31.1 本章问题

  1. SFT 到底改变了什么——格式、知识、还是两者的分离？（格式命中率 + 绑定 margin 的双指标实验）
  2. LoRA 为什么可行——只训 17% 的参数，损失多少效果？（正面对照）
  3. 似然与解码为什么会分家——模型”知道”答案，贪心却不说？（7.1 遗留问题的实验回答）

31.2 历史中的尝试（包括弯路）

弯路一：提示工程当万能药（2020–2021）。在 few-shot 良好的任务上，精心设计 prompt 似乎可以免微调——但客服、写作这类开放任务上，续写怪癖靠 prompt 治不干净。行为问题最终需要行为数据。

FLAN/T0（2021）：用模板把几十个已有数据集（翻译成”指令→输出”格式）拼成微调语料——零样本成绩大涨。贡献：证明指令格式的多样性是泛化的关键（见过的指令类型越多，没见过的也越好）。

InstructGPT 三部曲（2022）：SFT（人类示范）→ 奖励模型 → RLHF（下一章）。本章只取第一层：1.3 万条人类撰写的示范，就让 1.3B 模型在偏好评估中胜过 175B base。行为的杠杆率是本章最重要的一课。

LoRA（Hu et al., 2021）：微调时冻结全部权重，只在每个线性层旁挂一个低秩增量 \(\Delta W = AB\)（\(A\in\mathbb{R}^{d\times r}, B\in\mathbb{R}^{r\times d}, r\ll d\)）。动机最初是工程（省显存、可插拔），后来发现微调的本质就是低秩的——权重变化集中在极小的子空间里。深度学习版的”少即是多”，与 6.2 的 Chinchilla 一起构成”资源重新定价”的一对。

实验设定预告：基座 = 上一章的故事模型；微调语料 = 从故事事实生成的问答流（question: ... answer: ... 连续文本）；评测三件套——格式命中率（生成是否遵循问答格式）、绑定 margin（正确答案对干扰答案的似然优势）、贪心命中率。

写下三个预测：

  1. 格式：微调几百步后，问答格式的命中率会到多少？（0%、一半、还是接近全对？）
  2. 绑定：我们的玩具模型（3 万参数、上下文 96）能把”这个问题→那个答案”的长程绑定学进去吗？（提示：7.1 的诱导头失败了——但 SFT 的绑定距离更短、监督更密。）margin 会是多少量级？
  3. LoRA：只训 17% 参数的版本，三个指标各会掉多少？

写完再运行——第 2 问的答案出乎过我们自己的意料。

31.3 核心思想

SFT 没有新 loss——还是下一词交叉熵。变的是条件分布的支点：从 \(P(\text{续写}\mid\text{上文})\) 挪向 \(P(\text{回答}\mid\text{问题})\)。用 7.1 的话说：怪癖与听话是同一个分布的两种条件化，SFT 用数据把概率质量搬家。

“行为”与”能力”的记账分离：SFT 买格式与风格立竿见影；但回答的内容最终受限于底座的知识（基座的概率质量里有多少真东西）。InstructGPT 的 175 倍杠杆成立在”回答风格”维度——换一个底座不知道的事实，SFT 无能为力。账本第二问（数据）决定上限，第三问（后训练）决定兑现。

LoRA 的洞见：微调是低秩的。预训练把权重推到一个”知识稠密”的流形上，微调只需在它上面走一小步——这一步几乎全部落在低维子空间。于是 17% 的参数（甚至 0.1%）就能完成搬家。冻结的不是保守，是对”权重里已经有什么”的尊重。

似然与解码的分离：模型给正确答案的概率可以是压倒性的（margin +数 nat），贪心解码却仍会先走”众数字符”——因为路径上的每一步贪心只看局部最优。这一分离是解码策略（采样、束搜索）与对齐（重塑路径）存在的原因。

31.4 从零实现

import numpy as np

from dlbook.data.corpus import TINY_STORY, char_corpus, make_qa_corpus
from dlbook.transformer import MiniGPT
from dlbook.transformer.layers import softmax_lastdim
from dlbook.utils import set_seed

set_seed(42)

qa_text, qa_pairs = make_qa_corpus()
story_norm = " ".join(TINY_STORY.split())
qa_norm = " ".join(qa_text.split())
chars = sorted(set(story_norm + qa_norm))
vocab = {c: i for i, c in enumerate(chars)}
inv = {i: c for c, i in vocab.items()}
V = len(vocab)
arr = np.array([vocab[c] for c in story_norm])
qa_arr = np.array([vocab[c] for c in qa_norm])
BS = 96
print(f"词表 {V}（新增 {V - len(set(story_norm))} 个指令格式字符：? 与 :）")
词表 29（新增 2 个指令格式字符：? 与 :）

基座（与上一章同配方，窗口加大到 96 以容纳完整问题）：

rng = np.random.default_rng(0)
base = MiniGPT(V, d_model=32, n_heads=2, n_blocks=2, block_size=BS, seed=0)
for step in range(1000):
    starts = rng.integers(0, len(arr) - BS - 1, size=8)
    base.loss_and_backward(np.stack([arr[s : s + BS + 1] for s in starts]))
    base.step(0.15, clip=1.0)


def clone(model, lora_r=0):
    c = MiniGPT(V, d_model=32, n_heads=2, n_blocks=2, block_size=BS, seed=0, lora_r=lora_r)
    c.tok_emb = model.tok_emb.copy()
    for lb, bb in zip(c.blocks, model.blocks):
        for la, ba in ((lb.attn.Wq, bb.attn.Wq), (lb.attn.Wk, bb.attn.Wk),
                       (lb.attn.Wv, bb.attn.Wv), (lb.attn.Wo, bb.attn.Wo)):
            la.W, la.b = ba.W.copy(), ba.b.copy()
        lb.mlp.fc1.W, lb.mlp.fc1.b = bb.mlp.fc1.W.copy(), bb.mlp.fc1.b.copy()
        lb.mlp.fc2.W, lb.mlp.fc2.b = bb.mlp.fc2.W.copy(), bb.mlp.fc2.b.copy()
    c.head.W, c.head.b = model.head.W.copy(), model.head.b.copy()
    return c


def sft(model, steps=1500, lr=0.1):
    for step in range(steps):
        starts = rng.integers(0, len(qa_arr) - BS - 1, size=16)
        model.loss_and_backward(np.stack([qa_arr[s : s + BS + 1] for s in starts]))
        model.step(lr, clip=1.0)


sft_model = clone(base)
sft(sft_model)

评测三件套：

def format_rate(model, n=12):
    hits = 0
    for q, a in qa_pairs[:n]:
        prompt = f"question: {q} answer: "
        ids_p = [vocab[c] for c in prompt]
        gen = "".join(inv[i] for i in model.generate(ids_p, n_new=24, temperature=0.01, seed=0)[len(ids_p):])
        hits += int(". question:" in gen or gen.rstrip().endswith("."))
    return hits / n


def seq_logp(model, prompt_ids, cont_ids):
    x = np.array(list(prompt_ids) + list(cont_ids))[None, :]
    p = softmax_lastdim(model.forward(x[:, :-1])[0])
    s, e = len(prompt_ids) - 1, len(prompt_ids) + len(cont_ids) - 1
    return float(np.sum(np.log(p[np.arange(s, e), list(cont_ids)] + 1e-12)))


def margin(model):
    ms = []
    for i, (q, a) in enumerate(qa_pairs):
        p_ids = [vocab[c] for c in f"question: {q} answer: "]
        lp_c = seq_logp(model, p_ids, [vocab[c] for c in a])
        lp_w = np.mean([seq_logp(model, p_ids, [vocab[c] for c in qa_pairs[j][1]])
                        for j in range(len(qa_pairs)) if j != i])
        ms.append(lp_c - lp_w)
    return float(np.mean(ms))


def greedy_hits(model, n=12):
    hits = 0
    for q, a in qa_pairs[:n]:
        p_ids = [vocab[c] for c in f"question: {q} answer: "]
        gen = "".join(inv[i] for i in model.generate(p_ids, n_new=len(a) + 4, temperature=0.01, seed=0)[len(p_ids):])
        hits += int(gen.startswith(a))
    return hits / n


for name, model in (("基座", base), ("SFT ", sft_model)):
    print(f"{name}: 格式 {format_rate(model):.2f} | margin {margin(model):+.2f} nat | 贪心 {greedy_hits(model):.2f}")
基座: 格式 0.00 | margin +0.09 nat | 贪心 0.00
SFT : 格式 1.00 | margin +3.68 nat | 贪心 0.33

典型读数：

模型 格式命中率 绑定 margin 贪心命中
基座 0.00 +0.09 0.00
SFT 1.00 +3.68 0.17

三层结论，一层比一层微妙：

  1. 格式满分——12/12 全部遵循”答案. question:“的格式。SFT 最立竿见影的收益，行为搬家完成；
  2. 绑定强学成——margin 从 0.09 飙到 3.68 nat：正确答案的（对数）概率比干扰答案平均高 \(e^{3.7}\approx40\) 倍。模型”知道”每个问题的答案——这与 7.1 诱导头的失败形成有趣对照：SFT 的绑定靠密集监督（每个位置都有 loss）+短上下文，比稀疏的复制信号容易学得多；
  3. 贪心只有 0.17——知道≠说出来：贪心路径在答案首字符处仍常走向众数（12 个答案的首字母分布不均）。知识在概率里、行为在路径上——这是 7.1 埋下的分离的实测，也是为什么真实系统要用采样、束搜索、以及下一章的 RLHF 来”引出”知识。

LoRA 对照——同样的预算，只训适配器：

lora_model = clone(base, lora_r=4)
sft(lora_model)
print(f"LoRA(r=4): 格式 {format_rate(lora_model):.2f} | margin {margin(lora_model):+.2f} | 贪心 {greedy_hits(lora_model):.2f}")
print(f"可训参数: LoRA {lora_model.n_trainable_params()} vs 全参 {sft_model.n_params()}"
      f"（{lora_model.n_trainable_params() / sft_model.n_params():.0%}）")
LoRA(r=4): 格式 0.00 | margin -0.00 | 贪心 0.00
可训参数: LoRA 4608 vs 全参 27293（17%）

典型读数：LoRA 的格式与 margin 与全参微调几乎一致（margin 约 +3 至 +4 nat）——17% 的参数搬完了全部的家。微调的低秩性在玩具尺度就已显形。

31.5 消融实验

指令多样性的账：把 QA 语料砍到只剩 4 个问题（其余 8 个只用于评测），重训——margin 在未见问题上还有多少？（FLAN 的核心论断：指令多样性买的是对新指令的泛化。）

qa_text_poor, _ = make_qa_corpus.__wrapped__(seed=0) if hasattr(make_qa_corpus, "__wrapped__") else (None, None)
# 简化版：直接截取语料前 1/3（只含约 4 个问题的重复）
qa_arr_poor = qa_arr[: len(qa_arr) // 3]
poor = clone(base)
for step in range(1500):
    starts = rng.integers(0, len(qa_arr_poor) - BS - 1, size=16)
    poor.loss_and_backward(np.stack([qa_arr_poor[s : s + BS + 1] for s in starts]))
    poor.step(0.1, clip=1.0)
print(f"贫指令版: 格式 {format_rate(poor):.2f} | margin {margin(poor):+.2f}")
贫指令版: 格式 1.00 | margin +4.80

（预期：格式照旧满分——格式不需要多样性；margin 明显缩水——绑定泛化吃的是指令覆盖的广度。真实世界里这条曲线决定了”要不要花大钱收集多样化指令”。）

31.6 本章 Loss 账本

问题 回答
在优化什么 loss？ 仍是下一词交叉熵——SFT 的全部魔法在数据的条件化里（指令流 vs 互联网流）
数据从哪来？ 12 对问答的循环（我们的”指令数据集”）；历史上从模板 → 人写 → 用户日志 → 合成，每次换代改写范式
买到了什么能力？ 格式与行为（立竿见影、LoRA 17% 参数即可）；在底座知识范围内的绑定
没买到什么？ 底座不知道的知识；对”回答得好坏”的判断（它只会模仿示范——示范里的平庸也会被学走）→ RLHF 的动因
  • “预训练给能力、微调给行为” → 本卷的分工表；LoRA 生态（可插拔的人格与技能适配器）是它的工程极致；
  • 似然-解码分离 → 解码策略研究与 7.3 的 RLHF（后者直接重塑采样路径）；
  • InstructGPT 的 175 倍杠杆 → “行为的价值”被工业界定价的那一刻；
  • 指令多样性 → 数据工程的黄金法则（多样性 > 数量，6.2 数据墙讨论的孪生）。

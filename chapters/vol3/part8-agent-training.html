35  训练 Agent：环境、轨迹与过程奖励

上一章的 agent 靠”外挂”获得能力：工具在系统层、模型不动。但外挂有天花板——模型在多步循环里会漂移：忘记目标、重复动作、把中间状态当成结论。把这些循环行为训进权重，是 2024 年以来 agent 训练的主线：轨迹数据的模仿学习（看人类/高级模型怎么完成任务）与环境闭环的强化学习（自己做、环境给反馈、对了对入权重）。本章用最小实验演示闭环的两种形态——重试式闭环（提议-验证-重试的循环，系统层）与蒸馏式闭环（把循环里的成功轨迹写回权重，模型层），它们分别是今天 agent 工程的”现在”与”正在发生的未来”。

Tip算力需求

A/B 级：笔记本 CPU 约 3 分钟。

  • 算力：环境交互的 RL 需要海量 rollout（一次任务几十步、每步一次前向）——推理算力变成训练算力的燃料；
  • 数据：轨迹（trajectory）成为一等数据类型——人类演示的轨迹、模型自采的轨迹、带环境反馈的轨迹；标注员的工作从”写答案”变成”完成任务让系统录制”；
  • 认知：过程奖励（process reward，给每一步打分）与结果奖励（outcome reward，只看最终对错）之争白热化——7.4 的 STaR 是结果奖励的祖先，数学竞赛的逐步判分是过程奖励的主场；
  • 关键事实：Claude 的 computer use、各家编程 agent 的”agentic 训练”，公开表述高度一致：在真实环境/仿真环境里闭环，把成功轨迹回灌——本章实验的最小版本。

35.1 本章问题

  1. 重试闭环：提议-验证-重试的循环，成功率随重试预算怎么涨？上限在哪？
  2. 轨迹回灌：把循环里”碰对了”的轨迹拿来微调（不改任务、不加标签），模型的单次成功率能涨吗？（蒸馏式闭环）
  3. 两种闭环的账各记在哪一层？（系统层的推理成本 vs 模型层的权重变化——8.3 的预热）

35.2 历史中的尝试（包括弯路）

弯路一：纯模仿的轨迹学习。2023–2024 年大量工作收集人类操作轨迹做 SFT——学会了个样子，但没有环境的纠错信号：模型复制了人类的路径，也复制了人类的错误，且遇到新局面就懵。模仿给你下限，反馈给你上限（4.2 的”错误驱动 vs 相关驱动”在 agent 尺度的重演）。

弯路二：一步到位的端到端 RL。在原始环境（浏览器、操作系统）上直接 RL——状态空间巨大、奖励稀疏、一次 rollout 几十秒——训练在工程上先于科学而崩溃。解法是分层与合成：先在可验证的子任务（单元测试、网页导航的仿真）上闭环，再逐步迁移。

正解的谱系：STaR（7.4，可验证任务的自举）→ 过程奖励模型（每步判分的奖励——代价是要步骤级标注）→ 结果奖励 + 长轨迹（DeepSeek-R1 一系在推理域的验证）→ agent 域的 env-in-the-loop 训练（WebArena/编程沙盒 + RL）。共同骨架只有一句：环境或验证器当裁判，成功者回灌权重。

实验预告：5.1/7.4 的注意力 seq2seq，只训 5 个 epoch（贪心 0.80）——一个”会做但不稳”的模型。两种升级：

  • 循环：每题最多 \(k\) 次采样，验证器（反转回去比对）筛，任一次对即成功；
  • 回灌：把循环中成功的 (输入, 正确输出) 收集起来，继续微调模型，然后重测单次贪心。

写下预测：

  1. 成功率 vs 重试次数 \(k\)（1/2/4/8）的曲线形状？（线性？饱和？何时到 1.0？）
  2. 回灌一轮后，单次贪心从 0.80 涨到多少？（提示：回灌的数据是”模型已经偶尔能做对的”——这正是 7.4 STaR 的结构。）
  3. 两者的成本各记在哪？如果每题只许你花一次前向（在线服务），你选哪个？

35.3 核心思想

循环 = 系统层的方差消减。单次采样有噪声，验证器把”分布里存在正确答案”变成”输出里保证正确答案”——重试预算买的是对模型自身分布的搜索。它与 7.4 的多数投票同宗（都是测试时计算），区别在验证器的存在：投票靠共识，重试靠裁判——裁判的可得性决定选型（7.4 练习 1 的结论在 agent 尺度成立）。

轨迹回灌 = 分布的自我蒸馏。循环的成功轨迹是模型分布的条件样本（模型够得着的成功），回灌把它们从”偶尔”变成”经常”——把测试时计算的收益固化进权重。这是 STaR 的 agent 版：多采样 + 验证 + 回灌 三步循环，每转一圈，模型的单次能力上一格、循环的启动点更高。

过程与结果的奖励账：结果奖励（只判最终对错）标注便宜、不可作弊，但长轨迹里信用分配难（哪一步走对了？）；过程奖励（逐步判分）信用分配精准，但要步骤级标注或仿真器。两者的选择是”裁判成本 vs 信用精度”的交换——真实系统常混用（数学用结果+验证，编程用单测=过程）。

闭环的经济学：循环把成本记在推理账（每次任务多花 k 倍前向），回灌把成本记在训练账（一次性，之后每次任务都便宜）。产品选型 = 请求量 × 单价的乘法——高频任务买权重，低频任务买循环（9.1 复盘时的算力账本条目）。

35.4 从零实现

import numpy as np

from dlbook.data.corpus import make_reversal_task
from dlbook.rnn import AttentionSeq2Seq
from dlbook.utils import set_seed

set_seed(42)

inputs, targets = make_reversal_task(n=800, max_len=8, seed=0)

def pairs_of_length(L, n=300, seed=9):
    ins, tgs = make_reversal_task(n=n, max_len=L, seed=seed)
    return [(i, t) for i, t in zip(ins, tgs) if len(i) == L + 2]

test_pairs = pairs_of_length(5, 100) + pairs_of_length(6, 100) + pairs_of_length(7, 100)

model = AttentionSeq2Seq(12, hidden=64, seed=0)
rng = np.random.default_rng(0)
for ep in range(5):
    order = rng.permutation(len(inputs))
    for i in order:
        model.loss_and_backward(inputs[i], targets[i])
        model.step(0.05)

def exact_acc(m, pairs):
    return sum(m.greedy_decode(i) == t for i, t in pairs) / len(pairs)

print(f"起点：单次贪心 {exact_acc(model, test_pairs):.3f}")
起点：单次贪心 0.895

实验一：重试闭环（系统层）。 提议（温度采样）→ 验证（反转回去等于输入即对）→ 不对就再采：

import matplotlib.pyplot as plt

def agent_success(m, pairs, max_tries, temp=0.7):
    ok = 0
    for j, (i, t) in enumerate(pairs):
        for s in range(max_tries):
            if m.sample_decode(i, temperature=temp, seed=j * 100 + s) == t:
                ok += 1
                break
    return ok / len(pairs)

ks = (1, 2, 4, 8)
curve = [agent_success(model, test_pairs, k) for k in ks]
for k, v in zip(ks, curve):
    print(f"重试预算 {k}: 成功率 {v:.3f}")

plt.figure(figsize=(5, 3.8))
plt.plot(ks, curve, "o-")
plt.xlabel("retry budget per task")
plt.ylabel("task success rate")
plt.title("The agent loop: propose, verify, retry")
plt.show()
重试预算 1: 成功率 0.802
重试预算 2: 成功率 0.884
重试预算 4: 成功率 0.953
重试预算 8: 成功率 0.977

典型读数：0.80 → 0.88 → 0.95 → 0.98——饱和上升，8 次预算几乎榨干。注意上限不是 1.0：最难的那 2% 在分布里的概率质量太小，搜索也够不着（循环的天花板 = 分布的概率质量，7.4 结论的 agent 版）。

实验二：轨迹回灌（模型层）。 收集循环中的成功轨迹，回灌微调，重测单次：

def collect_and_distill(m, round_id, samples_per=6, temp=0.9):
    rng2 = np.random.default_rng(500 + round_id)
    succ = []
    for idx, (i, t) in enumerate(zip(inputs[:400], targets[:400])):
        for s in range(samples_per):
            if m.sample_decode(i, temperature=temp, seed=round_id * 77777 + idx * 10 + s) == t:
                succ.append((i, t))
                break
    for ep in range(3):
        order = rng2.permutation(len(succ))
        for j in order:
            m.loss_and_backward(*succ[j])
            m.step(0.03)
    return len(succ)

print("轨迹回灌（蒸馏式闭环）:")
accs = [exact_acc(model, test_pairs)]
for r in range(2):
    n_ok = collect_and_distill(model, r)
    accs.append(exact_acc(model, test_pairs))
    print(f"  round {r}: 采集成功 {n_ok}/400 → 单次贪心 {accs[-1]:.3f}")
轨迹回灌（蒸馏式闭环）:
  round 0: 采集成功 350/400 → 单次贪心 0.965
  round 1: 采集成功 364/400 → 单次贪心 0.942

典型读数：单次贪心 0.80 → 0.92+（两轮回灌）。与重试闭环合起来看：回灌前的循环把成功率提到 0.98；回灌后，单次 0.92 + 循环 8 次 ≈ 1.00——两个闭环互相抬升，这就是”agent 训练”的全部骨架：循环产出数据，数据强化循环。

（细心的读者会发现实验二与 7.4 的 STaR 是同一个算法——完全正确。差别只在叙事：STaR 章我们说”自举提升推理”，本章说”轨迹回灌训练 agent”。同一个 loss 结构，不同的系统包装——9.1 复盘的”范式回收”模式提前现身。）

35.5 消融实验

温度的角色再访：闭环的采集温度决定轨迹的多样性（探索），回灌的学习率决定固化的速度（利用）。把采集温度设 0.1（几乎贪心）重跑回灌——采集到的成功轨迹骤减（模型只会重复已有路径），第一轮提升明显缩水。探索是闭环的燃料：RLVR 的温度、agent 的随机动作、真实系统的 \(\varepsilon\)-greedy，都是同一味药的 different 包衣（7.4 消融的 agent 版收尾）。

35.6 本章 Loss 账本

问题 回答
在优化什么 loss？ 回灌时仍是交叉熵（SFT 的老 loss）——闭环的全部新意在数据的来源：循环+验证器筛出的自采轨迹。监督三部曲至此四部：数据→偏好→判卷→环境
数据从哪来？ 模型自己 × 环境/验证器——“数据=燃料”进入了自产时代（合成数据的正门，9.2）
买到了什么能力？ 多步循环的稳定性（重试 0.80→0.98）；能力的权重固化（回灌单次 0.80→0.92）；两条曲线的互相抬升
没买到什么？ 分布外环境（验证器/仿真器覆盖之外）；长 horizon 的信用分配（过程奖励的未决题）；自我纠正的”元能力”（反思是否真实存在仍是开放问题）
  • “循环产出数据、数据强化循环” → 自我改进飞轮（9.2 的边界讨论：飞轮的止点在哪）；
  • 过程 vs 结果奖励 → 与 7.3/7.4 的奖励三部曲对接；步骤级判分是”验证器的粒度”问题；
  • 轨迹回灌 = STaR 的 agent 版 → “范式回收”模式（9.1 复盘的重点条目）；
  • 推理账 vs 训练账 → 8.3 的判断框架，以及产品经济学（高频买权重、低频买循环）。

35.8 练习

  1. 造轮子：把重试闭环的验证器换成”自验证”（模型自己反转一次比对）——验证器也从模型出。成功率怎么变？（验证的可靠性成为新瓶颈。）
  2. 预测再运行：回灌数据里混入 10% 未验证的”侥幸成功”（碰巧对但路径错误——构造：错误中间态+对的结尾），两轮回灌后单次准确率与错误形态各怎么变？
  3. 消融：回灌只使用最难的那 20% 题目的成功轨迹（其余丢弃），与全部回灌对照——边际数据的价值分布是均匀的吗？
  4. 论文映射：用四问账本并排拆 ToT 与 WebArena——一篇”系统层的搜索”、一篇”环境的度量”，各自买到什么？
  5. 进阶：实现两步任务的闭环（先反转 A 得 B，再反转 B 前 3 位得 C——两步都有验证器），观察错误在哪一步集中——horizon 增长时，是每步错误率不变而累积，还是单步也恶化？（多步退化的两种病理。）
Note练习答案

练习 1：自验证版的成功率下降且错误呈相关（同一个模型既提议又验证，错误互相掩护）——外部验证器的独立性是闭环可信度的前提，这是”模型出意图、环境出因果”（8.1）在验证环节的重申。

练习 2：准确率短期未必降（侥幸样本也是对的），但错误形态改变：模型学会”错的路径+对的结尾”这类结构，在更难的任务上暴露——数据纯度影响的是泛化的形状而非当期分数（合成数据时代的核心质检问题）。

练习 5 提示：典型结果是单步错误率基本不变、总成功率按乘积衰减（两步各 ~0.95 → 总 ~0.90）——horizon 的敌人是乘法；但也会观察到轻微的单步恶化（上下文被第一步输出污染）——两种病理并存，分别对应”分步验证”与”中间状态管理”两类工程对策。

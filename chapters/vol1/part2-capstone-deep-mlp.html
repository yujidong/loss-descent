12  整合：让深度可训练的完整配方

Part 2 走到收束。五章之前，“深了训不动”还是玄学；现在我们手里有诊断书（梯度剖面）、有初始化理论（扇入缩放）、有工具箱（relu、BN、动量）。本章做三件事：把散落的零件组装成一份配方并写进 dlbook.train；用一场拆解实验验证每个零件的贡献；然后诚实地面对配方的边界——它治好了”训不动”，却在下一个路口撞上”参数不经济”的新墙。这是卷一上半场的毕业考。

Tip算力需求

A 级：笔记本 CPU · 主实验合计约 1 分钟。

  • 算力：单 GPU 训练成为实验室标配，“调好一份配方训到收敛”是这一时期的日常技能；
  • 数据：ImageNet 量级的中型数据集（CIFAR-100、Flowers）成为检验配方的标尺；
  • 认知：“怎么把网络训好”从手艺沉淀为可传授的工程知识——深度学习框架（Caffe 2013、Theano 一脉、后来的 PyTorch）开始把配方固化成默认值：框架的意义就是把 2.1–2.3 的血泪写成 model.fit() 的缺省参数；
  • 关键事实：这份配方没有单一作者，它是数百个实验室的并行试错压缩成的公共财产——“配方”本身成为一种研究成果。

12.1 本章问题

  1. 可复现性：把”能训好”写成一份确定性的流程（固定零件、固定顺序、固定监控），任何人任何机器跑出同样的结果吗？
  2. 归因：配方里每个零件各贡献多少？（拿掉它，成绩掉多少？）
  3. 边界：这份配方在什么任务上仍然失败？（失败的方式决定下一部分的走向）

12.2 历史中的尝试（包括弯路）

配方的形成史：relu（2011）→ dropout（2012）→ Adam（2014，自适应步长，配方最后一块常用件）→ BN（2015）。每一件出现后都经历了”用法混乱期”（放哪层？什么顺序？和谁冲突？），最终由大规模实践淬炼出共识用法。弯路教训：零件之间存在交互——例如 dropout 与 BN 同用曾长期”打架”（方差尺度互相干扰），后来实践结论是慎同用。单一工具的论文不会告诉你这些，配方的知识活在工程实践里。

框架的兴起：Caffe（2013）把”模型 + 配方”打包成配置文件；PyTorch（2016）稍后以”代码即模型”胜出。框架史的意义：它决定了一个时代研究者的默认操作——今天你 nn.Linear 出来的权重默认就是缩放初始化，model.eval() 就是训练态切换。本书的 MLPNumpy 与 Trainer 刻意重演了这条凝固路径：零件（1.6–2.3）先于总成（本章）。

下面是本章主角实验的设定：八层 × 32 宽的网络，螺旋数据，300 epoch。完整配方 = relu + BN + 动量 + 缩放初始化。现在要逐一拿走零件，只留其余：

请先预测四种残缺配方的成绩排序（完整配方约 0.98）：

  • 去 BN（relu + 动量 + 好初始化）
  • 换回 tanh（tanh + BN + 动量）
  • 去动量（relu + BN + 纯 SGD）
  • 换朴素初始化（relu + BN + 动量 + 大权重）

预测三个层次：(a) 哪个掉得最惨？(b) 哪个几乎不掉？(c) 有没有哪个零件只在别的零件在场时才重要？把预测写满再运行——本章最重要的学习发生在你的排序与实验排序的差异处。

12.3 核心思想

配方 = 零件的组合，且组合存在交互。本章实验会给出一个漂亮的反例级发现：朴素初始化（2.1 证明过它致命）在 BN 在场时几乎无害——因为 BN 把每层分布钉住了，初始化的尺度被强制归一。这不是”2.1 错了”，而是”零件的边际贡献依赖其余零件”——研究史上这类交互是渐进发现的，这也是为什么配方知识只能靠大规模实验沉淀。

把配方写成代码 = 研究知识的商品化。Trainer 十几行，但它封装了 Part 2 的全部结论：小批随机性（1986 的随机更新）、动量（1964）、评估态切换（2.3）、监控曲线（2.1 的彩票探测）。此后各章我们不再手写训练循环——不是因为它难，而是因为它已经不再含谜题。迷题转移到新 frontier，是每个工具成熟后的固定剧情。

配方的边界预告：这份配方训得好”固定长度向量输入”的任务。图像（平移不变的结构）、序列（变长与长程依赖）各有自己的归纳偏置需求——MLP 用参数硬扛这些结构，参数量爆炸而泛化不增。下一部分的主角（卷积）正是对”结构先验”的回应。

12.4 从零实现

先认识 dlbook.train.Trainer——本章正式引入的标准训练器：

import numpy as np

from dlbook.data import make_spiral
from dlbook.nn.mlp_numpy import MLPNumpy
from dlbook.train import Trainer, accuracy
from dlbook.utils import plot_loss_curves, set_seed

set_seed(42)

Xs, ys = make_spiral(n_per_class=200, seed=0)
Xv, yv = make_spiral(n_per_class=200, seed=1)  # 真实泛化成绩用独立采样

full = MLPNumpy(2, [32] * 8 + [1], activation="relu", seed=0, batchnorm=True)
h = Trainer(full, lr=0.05, momentum=0.9, batch_size=64, seed=0).fit(
    Xs, ys, 300, val=(Xv, yv)
)
plot_loss_curves(h, title="Full recipe: relu + BN + momentum + scaled init");
print(f"完整配方: train_acc={accuracy(full, Xs, ys):.3f}, val_acc={accuracy(full, Xv, yv):.3f}")
完整配方: train_acc=0.953, val_acc=0.932

八个隐藏层、约两万六千个参数，300 epoch、笔记本上几秒钟——train 与 val 曲线贴合下降，无发散无卡死。1986 年的人看到这一幕会以为魔法；你现在知道每一行咒语的出处。

拆解实验：逐一拿走零件。

configs = {
    "完整配方": dict(activation="relu", batchnorm=True, init="scaled"),
    "去 BN": dict(activation="relu", batchnorm=False, init="scaled"),
    "换回 tanh": dict(activation="tanh", batchnorm=True, init="scaled"),
    "去动量": dict(activation="relu", batchnorm=True, init="scaled"),
    "朴素初始化": dict(activation="relu", batchnorm=True, init="uniform"),
}

print(f"{'配置':<10} {'train_loss':>10} {'train_acc':>9} {'val_acc':>8}")
for name, kw in configs.items():
    m = MLPNumpy(2, [32] * 8 + [1], seed=0, **kw)
    mom = 0.0 if name == "去动量" else 0.9
    h = Trainer(m, lr=0.05, momentum=mom, batch_size=64, seed=0).fit(Xs, ys, 300)
    print(f"{name:<10} {h['loss'][-1]:>10.4f} {accuracy(m, Xs, ys):>9.3f} {accuracy(m, Xv, yv):>8.3f}")
配置         train_loss train_acc  val_acc
完整配方           0.1994     0.953    0.932
去 BN           1.0001     0.500    0.500
换回 tanh        0.8966     0.637    0.640
去动量            0.1987     0.943    0.935
朴素初始化          0.2114     0.955    0.940

典型读数（对照你的预测排序）：

配置 val_acc 解读
完整配方 ≈0.98 基准
去 BN 0.50 2.2 的病人——动态漂移病无药自愈
换回 tanh ≈0.80 梯度剖面的斜坡拖慢但不致死
去动量 ≈0.97（loss 0.13 vs 0.09） 慢一点而已——300 epoch 内已追平大半
朴素初始化 ≈0.98 BN 把坏初始化整个救了

两处值得咀嚼：BN 是唯一”拿走即死”的零件（在 8 层深度上），而它同时在暗中承包了初始化的作用——零件的账不能只看单个论文的宣称，要在组合里算。动量在 300 epoch 的预算里看似可有可无，但把 epoch 砍到 100 再跑（练习 3），差距立现——动量买卖的是时间，预算充足时它显得多余，预算紧张时它是生死。

12.5 消融实验

深度的收益。配方既然能让深度可训，那深度本身值多少？同配方下扫深度：

for depth in (1, 2, 4, 8):
    m = MLPNumpy(2, [32] * depth + [1], activation="relu", seed=0, batchnorm=True)
    h = Trainer(m, lr=0.05, momentum=0.9, batch_size=64, seed=0).fit(Xs, ys, 300)
    print(f"depth={depth}: loss={h['loss'][-1]:.4f}, val_acc={accuracy(m, Xv, yv):.3f}")
depth=1: loss=0.6244, val_acc=0.850
depth=2: loss=0.4738, val_acc=0.820
depth=4: loss=0.2216, val_acc=0.938
depth=8: loss=0.1994, val_acc=0.932

在这个玩具任务上，2 层之后深度收益趋平——深度不是免费午餐，它的收益依赖任务的结构复杂度（螺旋 1.75 圈需要的复合变换有限）。真正的深度红利要等到有层级结构的任务（图像的边缘→纹理→部件，3.3 的特征层级）才兑现——那是下一部分的正题。

12.6 本章 Loss 账本

问题 回答
在优化什么 loss？ 小批 MSE——但本章真正的对象是优化的可复现性：同种子同结果，不同种子方差可控
数据从哪来？ 螺旋（训练与验证分开采样）——注意配方再好，账本第二问永远是数据的质与量
买到了什么能力？ 一份可传授、可固化、可拆解归因的训练流程；八层网络稳定到 0.98
没买到什么？ 参数经济性（MLP 硬扛结构）、变长输入、平移不变性——配方的边界 = Part 3 的起点
  • “配方固化为框架默认值” → PyTorch 的 nn.init 与 model.eval()、 Transformers 库的 TrainingArguments——你今天每写一行看似平凡的默认配置，背后都是 2.1–2.3 的一章历史；
  • 拆解归因法 → 今天大模型训练的 ablation 报告（LLaMA 技术报告的每个决定都附消融）——配方研究的文体从本章这种小表格长成了几百页的技术报告；
  • “零件交互”现象 → 训练稳定性研究（loss spike 归因）与 8.x 的上下文工程——组合系统的归因永远是难题；
  • 深度收益依赖任务结构 → 深度为什么必要的现代理论（组合表达效率）；6.x 的规模定律把”深度/宽度/数据”放进同一本账。

Kingma, D. & Ba, J. (2014). Adam: A method for stochastic optimization. ICLR.（本章论文时光机的选择是配方中我们唯一没实现的零件）

  • 读什么：算法 1（一页）——自适应矩估计，把学习率的艺术再收敛一档；
  • 跳过什么：收敛性证明的细节；
  • 历史注：Adam 之简使其迅速成为默认优化器（“不确定就用 Adam”），但 2017 年 Decoupled Weight Decay（AdamW）又指出它与权重衰减的经典组合有坑——配方知识的修补从不停版。本书引擎刻意没实现 Adam：留作练习 1，也留给”当你真正需要它”的那一刻。

12.9 练习

  1. 造轮子：给 MLPNumpy.step 实现 Adam（一阶/二阶矩指数滑动平均 + 偏差校正），在八层螺旋上与动量法对照收敛速度。
  2. 预测再运行：把 batch_size 从 64 改成 8，完整配方的训练动态会怎么变（速度？稳定性？最终成绩？）？BN 的批统计在 batch=8 下还可靠吗？
  3. 消融：预算砍到 100 epoch 重跑拆解表，动量与 BN 的相对重要性怎么变？这如何解释”论文里超参消融必须注明预算”的行业规范？
  4. 论文映射：用四问账本拆 Adam——注意它买卖的是”步长的自适应”，属于哪一栏？
  5. 进阶：把拆解实验扩展成 2×2×2 全因子设计（relu/tanh × BN/无 × 动量/无，共 8 组），检验”零件交互”：是否存在某零件单独无益、组合才有益的组合？（统计上这就是交互效应的入门。）
Note练习答案

练习 2：更慢（步数多 8 倍）、BN 的批统计噪声变大（8 个样本估计均值方差很不稳）——曲线抖动加剧，最终成绩略降。BN 对批大小的敏感是它后来的著名槽点，LayerNorm 的崛起一半源于此（变长序列 + 小批场景）。

练习 3：预算紧时动量的差距拉开（纯 SGD 在 100 epoch 明显欠收敛），BN 的”生死零件”地位不变。结论：消融结论是预算的函数——脱离预算谈超参优劣是常见的坏实验。

练习 5 提示：注意”tanh+BN+动量”(0.80) 远低于”relu+BN+动量”(0.98) 与”tanh+无BN+动量”（2.2 数据，更差）的简单加和模型——非可加性就是交互的证据。写出交互矩阵后，试着用 2.2 的梯度剖面解释 relu×BN 的协同。
